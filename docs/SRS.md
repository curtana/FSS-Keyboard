## 1. 소개

### 1.1 목적
이 문서는 안드로이드 키보드 앱(이하 "시스템")이 **무엇을 해야 하는지**를 검증할 수 있는 형태로 정한다. 어떻게 만드는지는 HLD가 다룬다.

### 1.2 범위
- 하나의 안드로이드 입력기(IME) 앱이 **네 입력 모드**를 제공한다: 영문 쿼티, 한글 두벌식, 그래피티(영문·한글), 긋기 입력.
- 설정 앱 화면(설정, 입력 연습)을 포함한다.
- 배치는 **휴대폰 세로 화면** 기준으로 만든다(오너 결정, 2026-10-27). 입력기는 화면 방향을 고정할 수 없으므로, 가로 화면에서는 같은 배치를 그대로 보인다(FR-CMN-12). 가로·폴더블·태블릿 전용 배치는 만들지 않는다(TBD-8). 넓은 화면에서는 같은 배치의 **폭을 줄여 왼쪽·가운데·오른쪽에 둘 수 있다**(FR-CMN-14, 오너 결정 2026-11-02, FSS#25).
- **차기 버전(오너 결정, 2026-10-27):**
  - 기호 모드(모드 키 순환에 들어가는 독립 모드, 서브모드 아님)와 이모지 입력(TBD-4)
  - 스페이스바를 밀어 커서 옮기기(FR-TAP-12)
- **범위 밖(오너 결정, 2026-10-27):** 한자 변환. 휴대폰에서 얻는 것이 작고(아이폰 기본 키보드에도 없음), 빼면 한자 사전 라이선스 문제도 함께 없어진다. 조사 기록은 7장 TBD-13에 남긴다.

### 1.4 요구사항 표기
- **ID:** `FR-영역-번호`(기능), `NFR-번호`(비기능)
- **우선순위:** 필수(M) / 권장(S) / 선택(C)
- **검증 방법:** T 시험(자동 단위 시험) / D 시연(실기기 확인) / I 검사(코드·화면 확인) / A 분석

## 2. 전체 설명

### 2.1 제품 관점
- 시스템은 안드로이드 `InputMethodService` 기반의 독립 앱이다. 서버나 네트워크를 쓰지 않는다.
- 입력 결과는 안드로이드 `InputConnection`으로 현재 입력창에 전달한다.

### 2.2 기능 요약

| 영역 | 내용 |
|---|---|
| 공통 | 모드 전환, 입력창 종류별 자판, 조합 표시, 지우기, 여러 손가락 터치, 가로 화면 |
| 한글 조합 | 두벌식 규칙(받침, 겹받침, 도깨비불)을 모든 한글 입력에 공통 적용. **모음 병합 표는 입력 방식별**(FR-HGL-04) |
| 영문 쿼티 / 한글 두벌식 | 표준 탭 자판 + 편집 줄(탭, 방향키) + 숫자 줄. 페이지 전환·⇧ 키 없음. 글자·숫자 키 ↑ = 시프트 |
| 긋기 입력 | 자음 키 탭 = 자음(쌍자음은 전용 키, 시간 판정 없음), 모음 = 필순대로 획마다 손을 떼며 긋기(키와 무관, 획 모양(세로·가로)·그려진 자음 C 기준 위치·필순·연결 위치·오토마타 후보로 판정, 되돌리기 동작 없음, dp 길이 기준 없음). 두벌식 조합. 천지인 키, 둘레의 숫자 키와 기호 키 포함(이슈 #173) |
| 그래피티 | 단일 획 필기 입력(영문 Graffiti 1 방식, 한글 단일 획 체계), 한글·영문·숫자 획 안내표 팁(불투명 덮개) |
| 안내 표시 | 방향 안내, 현재 글자, 다음 글자(긋기 자판) |
| 입력 연습(옛 튜터 모드) | 입력 방법을 주제별로 골라서 짧게 연습(FSS#17. 기준값은 재지 않음) |
| 설정 | 표시·피드백, 입력 연습 열기 |

### 2.3 사용자
오너 본인(우선). 키보드 사용에 익숙하고, 긋기 입력과 그래피티를 새로 배우는 사용자.

- 두 자판은 키 자리 단위로 같은 배정을 쓴다(ㅣ 자리 = l 자리).
- **모드 키(PC 두벌식의 한/영 키 자리)는 네 모드 모두 맨 아랫줄 왼쪽**에 둔다. 배치는 모드마다 필요에 따라 다르게 둔다(오너 결정 2026-10-27). 모드 키는 네 모드 모두 **탭 = 모드 전환(FR-CMN-03), ↑ = 키보드 설정 화면(FR-CMN-13, 오너 결정 2026-11-02, 이슈 #205)**이고, ←·→는 탭과 같다(↓는 맨 아랫줄이라 쓸 수 없고, ←는 화면 끝이라 탭과 같음).
- **자판 키 영역 높이 = 네 모드 중 가장 높은 자판의 높이**(쿼티·두벌식 6줄 288dp)로 고정한다. 긋기 자판도 6줄 288dp다(쌍자음 줄, 이슈 #168. 0.37까지는 5줄 240dp + 위 빈 띠). 그보다 낮은 자판(그래피티 패드)은 **바닥에 맞춰** 그리고 위쪽 띠는 비워 둔다. 빈 띠는 터치를 받되 입력은 없다(아래 앱으로 터치가 새지 않게). 단, 그래피티 띠의 오른쪽 끝에는 획 안내표 버튼이 있다(FR-GRF-09, 입력이 아닌 토글). 긋기 자판 맨 윗줄(숫자 1~7) 키의 ↑ 나감은 창 위로 나가도 획 움직임을 계속 받으므로 보통 변 통과로 센다. 그래서 모드를 바꿔도 창 높이와 모드 키 위치가 그대로다(오너 결정 2026-10-27).
- **시스템 막대와의 관계(오너 결정 2026-10-28, 이슈 #93):** 위의 "바닥"은 화면 맨 아래가 아니라 **시스템 막대 위**다. 시스템 막대는 내비게이션 바(◁○□ 버튼 또는 제스처 줄)와, 시스템이 입력기 창 아래에 그리는 키보드 내리기(∨)·입력기 전환 버튼 줄을 말하며, 둘 중 큰 쪽을 쓴다. ① 6줄 자판(과 바닥 정렬한 낮은 자판)은 시스템 막대 위에 놓고, 막대 높이만큼 아래는 **입력 없는 여백**으로 둔다(OD-1 A). 그래서 모드 키·스페이스가 시스템 버튼 밑에 깔리지 않는다. 위에서 고정한 288dp는 키 영역 높이이고, 창은 이 여백만큼 더 높다. ② 여백은 **키보드 배경색**으로 칠해 키보드가 화면 끝까지 한 판으로 이어져 보이게 한다(OD-2 A). ③ 가로 화면에서 막대가 옆에 있으면(3버튼 내비게이션) **그 폭만큼 옆도 같은 여백으로 비운다**(OD-3 A). FR-CMN-12의 같은 배치는 남은 폭 안에서 지킨다. 여백은 빈 띠와 같게 입력이 없고 아래 앱으로 터치가 새지 않는다(시스템 버튼 자체의 터치는 시스템이 받는다). ④ **자판 폭을 줄이면(FR-CMN-14, FSS#25)** 남은 폭(③을 뺀 가용 폭) 안에서 자판을 왼쪽·가운데·오른쪽에 두고, 남는 자리는 ①·②와 같은 입력 없는 여백(키보드 배경색)이다. 창 높이·바닥은 그대로다.
- ⌫·↵ 위치는 자판별 관례를 따른다(쿼티·두벌식은 **⌫ = 편집 줄 오른쪽 끝, ↵ = 아랫글자 줄(z 줄) 오른쪽 끝**(오너 결정 2026-11-02, 이슈 #198. 0.46까지는 ⌫ = 아랫글자 줄 오른쪽, ↵ = 맨 아랫줄 오른쪽), 긋기 자판은 오른쪽 열). 맞추는 것은 모드 키뿐이다.

C가 있으면 ㅏ / ㅗ 상대 크기, ㅜ / ㅓ·ㅢ, ㅠ / ㅟ의 x 경계, "아래" 구역(ㅜ ②·ㅠ ③)의 시작 높이 조건은 쓰지 않는다(낱모음에만. 이슈 #192). 그다음 조립기는 **오토마타**(지금 상태에서 올 수 있는 모음·겹모음)와 **필순 규칙**(왼쪽 → 오른쪽, 위 → 아래, SWIPE 3.6.2 필순 표)으로 지금까지의 획 열로 될 수 있는 **모음 후보**를 유지하고(SWIPE 3.6.2 다음 후보 표, 정본), 다음 획은 그 후보 가운데 **연결 위치 구역**(앞 획의 오른쪽·아래, 어느 쪽·어느 높이, SWIPE 3.6.3)에 드는 하나로 정해야 한다. 후보 밖 해석은 하지 않는다. 첫 획의 모호함(세로 = ㅣ 또는 ㅗ·ㅛ의 점, 가로 = ㅡ 또는 ㅓ·ㅕ의 점)은 C가 있으면 첫 획에서 C로 정하고(ㄱㆍ → 고), 낱모음이면 둘 다 후보로 남겨 둘째 획으로 정한다(ㅣ → ㅗ, ㅡ → ㅓ). **판정 순서:** 탭/획 → 획 모양(축, 필순 방향 확인) → C 기준 역할 → 후보와 연결 위치(0.43까지의 마지막 단계 "길이"는 삭제. 단계 이름 정리 이슈 #212). 구역은 쪽·높이만 보고 **dp 길이·닿음·거리 상한은 보지 않는다**(획이 떨어져도 됨). **상대 크기 비교는 오너가 정한 두 곳뿐이다(오너 2026-11-01: "ㅏ와 ㅗ는 확연히 다르지. ㅏ는 ㅣ 다음에 두 번째로 처음 길이보다 짧은 획이 들어오고, ㅗ는 짧은 획 뒤에 ㅡ 긴 획이 들어오는데, 둘은 순서와 상대적인 크기 차이로 구분할 것 같은데."
