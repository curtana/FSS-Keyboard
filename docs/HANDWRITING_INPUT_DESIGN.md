# 손글씨 글자 인식 설계

- 버전: **0.1** (2026-11-14)
- 상태: 설계 초안. 오너 결정(2026-11-13, FSS#64·#83)을 규칙으로 옮겼다. **자람 표와 자리 규칙은 활자체 정자 획순을 기준으로 손으로 만든 것이고 사람 획으로 재지 않았다.** 기준값은 모두 확정 전이다(12장). 오너가 골라야 하는 것은 13장에 모았다.
- 관련 문서: [SRS.md](SRS.md) 0.84(요구사항 FR-HWR, 3.7A절), [HLD.md](HLD.md) 0.77(5B장), [REQUIREMENTS.md](REQUIREMENTS.md) 0.32(UR-C9~C15)
- 이 문서의 자리: 그래피티 모드의 **새 인식 방식**(평소 글자 모양 인식)의 규칙 정본이다. 긋기 입력의 [SWIPE_INPUT_DESIGN.md](SWIPE_INPUT_DESIGN.md)와 같은 자리다. 지금의 한 획 약속 글자 규칙은 저장소 밖의 그래피티 규칙 문서(SRS의 "GRAFFITI n.n")가 정본이고, 그 요구사항은 단계가 올 때까지 유효하다(11장, SRS 3.7A.1). 이 문서를 새 공개 문서로 둔 것은 PM 판단이다(FSS#91 작업지시서, 오너 확인 항목 13장 12번).

## 1. 개요

**하려는 것.** 그래피티 모드의 입력을 한 획 약속 글자에서 **평소 쓰는 글자 모양**으로 바꾼다. 한글은 음절 모양대로, 영문은 활자체 모양대로 쓴다.

> 오너 결정(2026-11-13, FSS#64, 대화 원문): "기존 그래피티를 버리고 한글 문자를 인식시켜서 입력을 받자 그럼 한글 아는 사람은 다 쓸 수 있고 영어도 활자체를 기준으로 인식하면 문제의 소지가 없을 것 같아"

- 약속 글자를 따로 배우지 않아도 쓰게 하는 것이 목적이다.
- 영문 필기체는 이번 범위가 아니다(오너 의견 2026-11-13, FSS#83: "추가 한다면 필기체도 반양할 생각이지만 나느 필기체를 안쓰니까 나중에 고려하자고").
- **새 방식이 지금 방식보다 빠르거나 정확한지는 재지 않았다.** 단계마다 잴 것을 11장에 적었다.
- 모드 이름("그래피티"), 모드 키 순환, 창 높이, 보조 줄의 자리는 바꾸지 않는다.

### 1.1 용어

| 용어 | 뜻 |
|---|---|
| 획 | 손가락을 대서 뗄 때까지의 한 번. 점 열과 시각을 가진다 |
| 탭 | 움직임이 탭 경계(지금 8dp) 안인 획. 글자의 **점**이거나 제어 동작이다(8.5절) |
| 기본 획 | 글자를 이루는 획의 종류(3장). 획 하나는 기본 획 하나나 한 획 글자 하나로 분류된다 |
| 묶음 | 한 글자를 이루려고 모인 획들. 쓴 차례대로 가진다 |
| 묶음의 상태 | **글자**(아는 글자다) / **앞부분**(아직 글자는 아니지만 어떤 글자의 앞부분이다) / **아님**(아무것도 아니다) |
| 열린 묶음 | 획이 더 붙을 수 있는 묶음. 한 번에 하나뿐이다 |
| 열린 글자 | 상태가 글자이면서 획을 더하면 다른 글자로 자랄 수 있는 것(예: 소문자 l) |
| 끝 글자 | 더 자랄 곳이 없는 글자(예: 소문자 t, e). 완성되는 자리에서 닫힌다 |
| 닫힘 | 묶음에 획이 더 붙지 않게 되는 것. 닫힌 글자는 다시 열지 않는다 |
| 확정 | 글자가 입력창에 굳는 것. 영문·숫자는 닫힘과 함께 확정된다. 한글은 자모가 닫혀도 음절은 조합 중으로 남는다(7장) |
| 자람 표 | 묶음의 상태와 새 획의 종류로 다음 상태를 찾는 표(4장) |
| 자리 규칙 | 새 획과 묶음의 자리 관계(닿음, 가로지름, 위·아래·왼쪽·오른쪽)와 칸 안의 자리로 자람을 가르는 규칙(5장) |
| 붙는 쌍 | 따로 쓰려던 두 글자의 획이 한 글자로 합쳐지는 경우(예: c 다음 l이 d) |
| 칸 | 패드에 고정된 글자 한 자리. 가로 3줄 × 세로 4줄(6장) |
| 문자 칸 / 숫자 영역 | 글자를 쓰는 칸 / 숫자·기호를 쓰는 영역. 숫자 영역은 칸이 아니다 |
| 사분 자리 | 한글 칸을 넷으로 나눈 자리: **왼위, 오위, 왼아래, 오아래**(7장) |
| 세 띠 | 영문 칸을 기준선 둘로 나눈 높이: **솟음**(위) / **가운데** / **내림**(아래) |
| 새 방식 구간 | 새 인식 방식이 적용되는 언어 상태·영역. 단계마다 넓어진다(11장) |

## 2. 원칙

### 2.1 자람 원칙 (오너 원칙)

> 오너 의견(2026-11-13, FSS#83, 대화 원문): "항상 element 구성을 묻는데 추가하는 획이 구성하는 가장 큰요소를 그 엘리먼트라고 보면 되는 것이지. i에 위쪽 수평획을 추가면 그때 t 가 되는 것이지 획추가에 따른 가능성과 방향을 열어 두고 있어야지 추가한 획이 인식이 안되면 독립된 글자가 시작된 것이고 쉽게 이야기해서 대문자"

- 획이 더해질 때마다 **지금 묶음 + 새 획이 이루는 가장 큰 글자**로 본다. 글자는 열어 두고, 다음 획으로 바뀔 수 있다(조합 중 글자를 갈아 끼운다).
- 새 획이 지금 묶음과 합쳐 아는 글자(나 그 앞부분)가 되지 않으면 **새 글자가 시작된 것**이다.
- 글자가 끝났는지를 따로 묻지 않는다. **시간으로 끊지 않는다**(시간 기준값이 없다).

### 2.2 닫힘 (오너 원칙)

> 오너 의견(2026-11-13, FSS#83, 대화 원문): "A의 획이 완성된 뒤에 추가로 오는 것은 별개의 문자이지"

- 더 자랄 곳이 없는 글자(끝 글자)는 **완성되는 자리에서 닫힌다.** 그 뒤의 획은 새 글자의 첫 획이다.

### 2.3 나눔 원칙 (오너 원칙)

> 오너 의견(2026-11-13, FSS#83, 대화 원문): "l,l,1은 필기로 구분할 방법이 없잖아 그럼 나눠야 하는 것이지 그것이 구분할 방법이 있다면 통합하는 것이고"
> 오너 의견(같은 날): "ㅣ와 l은 구분이 힘들잖아 그러니깐 이때는 한/영 구분이 필요한 것이지"
> 오너 의견(같은 날): "다만 분석후 한영을 구분해야하고 연문 대소문자를 구분해야 한다면 지금처럼 한/영을 구분하고 시프트키를 받도록 유지해야지"

- 모양으로 가를 수 없는 글자끼리는 **입력 구분**으로 나눈다. 가를 방법이 있으면 합친다.
- 지금 정한 경계(분석의 판단을 따른 것이고 사람 획으로 재지 않았다):

| 경계 | 정함 | 수단 | 모양으로 못 가르는 예(손으로 판단) |
|---|---|---|---|
| 한글 / 영문 | 나눔 | 한영 전환(구석 탭) | ㅣ·l, ㅇ·o, ㄴ·L, ㅜ·T, ㅐ·H, ㅌ·E |
| 소문자 / 대문자 | 나눔 | 시프트·캡스록 | c·C, o·O, s·S, v·V, w·W, x·X, z·Z, l·I |
| 글자 / 숫자 | 나눔 | 숫자 영역 | l·1, o·0, ㄱ·7 |
| 글자 / 기호 | 나눔 | 기호 대기(탭 뒤의 획) | 하이픈·ㅡ, 마침표·점, 빗금·ㅅ의 첫 획 |
| 정자 / 필기체 | 범위 밖 | – | – |

- 높이를 재면 c·C처럼 크기만 다른 쌍을 가를 방법이 생길 수 있다. 손가락으로 기준선에 맞춰 쓴 정확도는 재지 않았다. 지금은 시프트를 유지하고, 수집에서 함께 잰다(11장).

### 2.4 획은 바로 앞의 열린 묶음에만 붙는다 (설계 규칙)

- 새 획이 붙을 수 있는 곳은 **지금 열린 묶음 하나**뿐이다. 이미 닫힌 글자를 자리로 찾아 다시 열지 않는다. 지금 입력기의 "확정된 글자는 다시 열지 않는다"(SRS FR-CMN-07)와 같은 생각이다.
- 그래서 **나중에 찍는 획**(낱말을 다 쓴 뒤 찍는 i의 점, t의 가로)은 받지 않는다. 받을지는 오너가 정한다(13장 5번).

### 2.5 묶음의 세 상태와 막혔을 때 (설계 규칙)

- 상태가 **앞부분**인 묶음을 따로 둔다. 두지 않으면 여러 획 글자(f, x, ㅂ, ㅍ)를 끝까지 쓸 수 없다.
- 열린 묶음에 새 획이 붙지 않으면: 묶음이 **글자**면 그 글자를 확정하고 새 획으로 새 글자를 시작한다. 묶음이 **앞부분**이면 묶음 안에서 마지막으로 글자였던 지점까지를 확정하고, 그 뒤의 획은 버리고, 새 획으로 새 글자를 시작한다.
- 새 획이 새 글자의 시작으로도 아무것도 아니면 입력이 없다(9.3절).

## 3. 기본 획

**활자체 정자 획순을 기준으로 손으로 만든 목록이고 사람 획으로 재지 않았다.** 분류 정확도는 미측정이다.

| 이름 | 모양과 방향 | 쓰이는 곳(예) |
|---|---|---|
| 세로 | 위 → 아래 직선 | l, t·k·b·h의 첫 획, ㅣ |
| 가로 | 왼쪽 → 오른쪽 직선 | t·f의 둘째 획, ㅡ |
| ＼ | 왼쪽 위 → 오른쪽 아래 사선 | x·y의 첫 획, ㅅ의 둘째 획 |
| ／ | 오른쪽 위 → 왼쪽 아래 사선 | x·y의 둘째 획, ㅅ의 첫 획 |
| 점 | 탭 | i·j의 점, ㅊ·ㅎ의 꼭지 |
| 갈고리 세로 | 위에서 굽어 내려오는 세로 | f의 첫 획 |
| 내림 갈고리 | 내려가서 왼쪽으로 굽는 세로 | j의 첫 획 |
| 꺾임 | `<` 꼴(오른쪽 위 → 왼쪽 → 오른쪽 아래) | k의 둘째 획 |
| ㄱ 꼴 | 가로로 가다 아래로 꺾음 | ㄱ, ㅋ·ㄹ·ㅁ의 획 |
| ㄴ 꼴 | 아래로 가다 오른쪽으로 꺾음 | ㄴ, ㄷ·ㅌ·ㄹ의 획, 대문자 L |
| 고리 | 닫힌 둥근 획 | ㅇ, ㅎ의 셋째 획, o |
| 굽은 획 | 오른쪽으로 볼록한 획(`⊃` 꼴) | 대문자 D·P·B·R의 획 |

- **방향이 반대인 직선은 글자의 획이 아니다.** 오른쪽 → 왼쪽 가로는 ⌫ 획, 아래 → 위 세로는 시프트 획이다(8.2절). 가로를 오른쪽에서 왼쪽으로, 세로를 아래에서 위로 쓰는 사람이 얼마나 되는지는 미확인이다.
- **한 획 글자**는 기본 획으로 쪼개지 않고 글자 모양 그대로 분류한다(4.1절의 한 획 소문자 스무 자 등).
- 1단계가 쓰는 기본 획은 세로, 가로, ＼, ／, 점, 갈고리 세로, 내림 갈고리, 꺾임 여덟이다. ㄱ 꼴, ㄴ 꼴, 고리는 2단계, 굽은 획은 대문자 단계에 쓴다.
- 길이로 획의 종류를 가르지 않는다(짧은 세로와 긴 세로는 같은 "세로"다). 가르는 것은 자리 규칙이다.

## 4. 자람 표

**아래 표는 모두 활자체 정자 획순을 기준으로 손으로 만든 표이고 사람 획으로 재지 않았다.** 사람들이 실제로 몇 획으로, 어떤 차례로 쓰는지는 미확인이다. 표기: `→` 획 하나를 더해 자람, **끝** 더 자랄 곳이 없음, (앞) 아직 글자가 아닌 앞부분.

### 4.1 영문 소문자 26 (1단계)

높이: 솟음(위로 솟는 글자), 가운데, 내림(아래로 내려가는 글자). 높이는 표시일 뿐이고 1단계 판정에 쓰지 않는다(5.3절).

| 글자 | 정자 획 수와 차례 | 1단계에서 받는 모양 | 자람 | 높이 |
|---|---|---|---|---|
| a | 2: 고리(c 꼴) → 오른쪽 짧은 세로 | **한 획**(고리에서 이어 세로) | 끝 | 가운데 |
| b | 2: 긴 세로 → 오른쪽 아래 고리 | **한 획** | 끝 | 솟음 |
| c | 1 | 한 획 | 끝 | 가운데 |
| d | 2: 고리 → 오른쪽 긴 세로 | **한 획** | 끝 | 솟음 |
| e | 1 | 한 획 | 끝 | 가운데 |
| f | 2: 갈고리 세로 → 가로 | 두 획 | 갈고리 세로(앞) → f(끝) | 솟음 |
| g | 2: 고리 → 아래로 내려가는 갈고리 | **한 획** | 끝 | 내림 |
| h | 2: 긴 세로 → 아치 | **한 획** | 끝 | 솟음 |
| i | 2: 짧은 세로 → 점 | 두 획 | 세로(l) → i(끝) | 가운데 |
| j | 2: 내림 갈고리 → 점 | 두 획 | 내림 갈고리(앞) → j(끝) | 내림 |
| k | 2: 긴 세로 → 꺾임 | 두 획 | 세로(l) → k(끝) | 솟음 |
| l | 1 | 한 획(세로) | **열린 글자.** → t, k, i | 솟음 |
| m | 1(세로에서 이어 아치 둘) | 한 획 | 끝 | 가운데 |
| n | 1(세로에서 이어 아치) | 한 획 | 끝 | 가운데 |
| o | 1 | 한 획 | 끝 | 가운데 |
| p | 2: 내려가는 세로 → 고리 | **한 획** | 끝 | 내림 |
| q | 2: 고리 → 내려가는 세로 | **한 획** | 끝 | 내림 |
| r | 1(세로에서 이어 어깨) | 한 획 | 끝 | 가운데 |
| s | 1 | 한 획 | 끝 | 가운데 |
| t | 2: 세로 → 가로 | 두 획 | 세로(l) → t(끝) | 솟음 |
| u | 1 | 한 획 | 끝 | 가운데 |
| v | 1 | 한 획 | 끝 | 가운데 |
| w | 1 | 한 획 | 끝 | 가운데 |
| x | 2: ＼ → ／ | 두 획 | ＼(앞) → x(끝) | 가운데 |
| y | 2: 짧은 ＼ → 긴 ／ | 두 획, 그리고 한 획(u 꼴에서 이어 갈고리) | ＼(앞) → y(끝). 한 획 y는 끝 | 내림 |
| z | 1 | 한 획 | 끝 | 가운데 |

**읽히는 것.**
- 한 획으로 받는 글자는 스무 자(a b c d e g h l m n o p q r s u v w y z)이고, 반드시 여러 획인 글자는 f, i, j, k, t, x 여섯 자다. y는 두 모양을 다 받는다.
- **정자가 두 획인 a, b, d, g, h, p, q는 1단계에서 한 획으로 이어 쓴 모양만 받는다**(굵게 적은 칸). 두 획으로 쓴 것도 받으면 c·o·l이 모두 열린 글자가 되어 흔한 글자 쌍(ch, cl, ol, lo)이 붙는다(4.2절). 받을지는 오너가 정한다(13장 5번). 두 획으로 쓰는 사람의 비율은 미확인이다.
- 그래서 1단계의 **열린 글자는 l 하나**이고, 앞부분은 갈고리 세로, 내림 갈고리, ＼ 셋이다. **1단계의 열린 묶음은 늘 획 하나**다(두 획째에 끝 글자가 되거나 붙지 않는다).
- 세로 하나는 길이와 상관없이 l로 보이고, 위에 점이 오면 i로 바뀐다(l → i). 짧은 세로와 l을 홀로 있을 때 가르지 않는다.
- 3획 k, 2~3획 m, 2획 n·r·v·u·w는 받지 않는다.

**1단계 자람 표(상태 × 새 획).** 자리 조건은 5.1절이다.

| 열린 묶음 | 새 획 | 자리 조건 | 결과 |
|---|---|---|---|
| (없음) | 한 획 끝 글자 열아홉(l을 뺀 한 획 글자) | – | 그 글자, 닫힘·확정 |
| (없음) | 세로 | – | l, 열림(조합 중) |
| (없음) | 갈고리 세로 / 내림 갈고리 / ＼ | – | 앞부분, 열림(입력창 표시 없음) |
| (없음) | 가로, ／, 꺾임 | – | 아님: 입력 없음, 오류 진동 |
| l | 가로 | P1 가로지름 | t, 닫힘·확정 |
| l | 꺾임 | P2 닿음 | k, 닫힘·확정 |
| l | 점 | P3 위의 점 | i, 닫힘·확정 |

| 그 밖의 모든 짝, 자리 조건이 안 맞는 짝 | | | 붙지 않음 → 2.5절(앞 묶음 마무리, 새 획은 새 글자의 시작) |

### 4.2 소문자에서 붙는 쌍

판단: **풀림**(표·모양으로 갈림), **자리**(자리 규칙으로 갈림, 기준값 미측정), **안 생김**(1단계가 두 획 변형을 받지 않아서). 손으로 한 판단이고 재지 않았다.

| 번호 | 앞 글자 + 뒤 글자의 첫 획 | 붙어서 될 것 | 낱말 예 | 1단계 판단 |
|---|---|---|---|---|
| 1 | c + 세로 | d, a, q, g | ch, ck, cl, ct, ci | 안 생김. 두 획 변형을 받으면 생기고, 한 칸에 겹쳐 쓰면 가를 수 없다 |
| 2 | o + 세로 | a, d, q, g | ol, ok, oh, ot, oi | 안 생김(1과 같다) |
| 3 | l + 고리 | b | lo, la, ld | 안 생김(1과 같다) |
| 4 | l + 아치 | h | – | 풀림. 아치로 시작하는 글자가 없다 |
| 5 | l + 꺾임 | k | lc(드묾) | 자리(P2). c의 둥근 획과 꺾임을 획 분류가 갈라야 한다(약함) |
| 6 | l + 가로 | t | l 다음 하이픈 | 풀림. 가로 한 획인 소문자가 없고 하이픈은 기호 대기 뒤에 온다 |
| 7 | l + 점 | i | l 다음 마침표 | 자리(P3). 기호 대기의 탭을 세로 위에 찍으면 i가 된다(8.5절) |
| 8 | 세로 + 세로 | – | ll, lt, il | 풀림. 세로 둘은 소문자 표에 없어 끊긴다 |
| 9 | ＼ + ／ | x, y | – | 한 글자 안의 구분. 자리(P4) |
| 10 | v + v, n + 아치, u + 세로 | w, m, 두 획 u | vv, rn | 안 생김 |
| 11 | 같은 글자 반복 | – | oo, ee, ss, tt | 풀림. 끝 글자에는 획이 붙지 않는다. "ll"은 8번 |

- 남는 자리 판단은 5번·7번·9번 셋이다.
- 잘못 붙었을 때 빠져나오는 길은 글자 닫기 동작이다(8.4절).

## 5. 자리 규칙

**손으로 만든 규칙이고 사람 획으로 재지 않았다.** 기준값은 모두 확정 전이고 12장에 값마다 정하는 방법을 적었다. 아래의 "시작값"은 구현을 시작하려고 둔 설계 기본값이다.

### 5.1 획끼리의 자리 (1단계가 쓰는 것)

| 이름 | 쓰이는 곳 | 조건 | 기준값 |
|---|---|---|---|
| P1 가로지름 | l + 가로 = t, 갈고리 세로 + 가로 = f | 가로획이 세로획을 **가로지르거나 닿는다**: 가로획의 둘레를 닿음 허용 오차만큼 넓힌 것이 세로획과 만난다 | V1 닿음 허용 오차 |
| P2 닿음 | l + 꺾임 = k | 꺾임 획이 세로획의 **오른쪽**에 있고, 꺾인 점(가장 왼쪽 점)이 세로획에 닿는다(허용 오차 안) | V1 |
| P3 위의 점 | l + 점 = i, 내림 갈고리 + 점 = j | 점이 앞 획의 **맨 위 점보다 위**에 있고(허용 오차만큼은 아래여도 됨), 가로로 앞 획의 맨 위 점에서 점 가로 범위 안이다 | V1, V2 점 가로 범위 |
| P4 x / y | ＼ + ／ | 둘째 획이 첫 획에 닿거나 가로지른다(V1). 그 위에서 둘째 획의 아래 끝이 첫 획의 아래 끝보다 **내림 비율 넘게 아래**면 y, 아니고 가로지르면 x. 닿기만 하고 내려가지 않으면 붙지 않는다 | V1, V3 내림 비율 |

- 가로지름·닿음은 **획끼리의 자리**라 칸의 기준선과 상관없다.
- 긋기 입력의 모음 조립(SWIPE 3.6절)과 같은 종류의 판정이다. 다른 점은 자음 획도 있고 꺾임·고리가 있다는 것이다.

### 5.2 새 획과 묶음의 위·아래·왼쪽·오른쪽 (2단계가 쓰는 것)

- 한 자모 안의 획 관계를 가른다: ㅋ의 가로는 ㄱ 둘레 **안**, "그"의 ㅡ는 ㄱ **아래**. ㅏ의 가로는 세로의 **오른쪽**, ㅓ의 가로는 **왼쪽**. ㅜ의 세로는 가로 **아래**에서 가운데로 내려가고, ㅢ의 ㅣ는 가로의 **오른쪽**에서 위로 솟는다.
- 기준은 묶음의 둘레(획들을 싸는 사각형)와 새 획의 시작점·끝점이다. 길이로 가르지 않는다. 기준값은 2단계 설계에서 정한다(12장 V5).

### 5.3 영문의 세 띠

- 영문 칸에는 기준선 둘(가로 점선)이 있어 칸을 솟음 / 가운데 / 내림 세 띠로 나눈다. 기준선의 자리는 시작값으로 칸 높이의 위에서 1/4, 3/4이다(12장 V4. 한글 칸의 사분 점선 가로줄과 겹치지 않는 자리).
- **1단계에서 세 띠는 쓰는 자리를 잡아 주는 안내이고 판정에 쓰지 않는다**(정해질 때까지의 기준, 13장 6번). 1단계의 자리 판단(P1~P4)은 모두 획끼리의 자리로 된다.
- 높이를 판정에 넣으면 생기는 것(재지 않았다): 세로 하나의 l과 i의 앞부분을 가름, i의 점과 기호 대기 탭을 가름, 크기만 다른 대소문자 쌍을 가름. 붙는 쌍(c + 세로 = d)은 높이로 풀리지 않는다.

> 오너 결정(같은 날): "한글 인식 사격영역은 그려줘야 그래야 쓸수 있어 사분영역도 점선으로 표시해주고"
> 오너 결정(같은 날): "한칸을 기준으로 두칸은 그 두배가 되야 하는 것이지 영역을 늘리고 줄이면 안돼"
> 오너 결정(같은 날): "영역도 두개를 그려야 하는 것이고", "한글은 정사각형이 아니라 조금 길죽한 세로가 더 긴 모양의 칸을 사용하지"
> 오너 결정(같은 날): "3:4로"

- 칸은 패드에 고정된 네모다. **가로 : 세로 = 3 : 4**, 곧 **가로 3줄 × 세로 4줄**이다. 줄 높이 h(SRS FR-SET-06, 기본 48dp, 40~64dp)에 묶여 칸 = 3h × 4h이고, 기본 줄 높이에서 **144 × 192dp**다(h 40dp면 120 × 160dp, 64dp면 192 × 256dp).
- 칸 높이 4h는 패드 높이와 같다(그래피티 5줄 = 패드 4줄 + 보조 줄 1줄, SRS FR-GRF-01).
- **칸 크기는 칸 수에 따라 변하지 않는다.** 칸 수를 늘리면 같은 크기의 칸이 더 생긴다. 칸을 좁혀 더 넣지 않는다.
- **영문도 같은 칸을 쓴다**(한 글자 한 칸. 한 칸뿐이면 그 칸에 겹쳐 쓴다). 이 줄은 FSS#91 이슈 본문 "정해진 것"의 PM 정리이고 오너 원문은 없다(13장 6번에서 함께 확인한다).
- 3 : 4 칸에 손가락으로 음절 한 자를 쓰기에 충분한지는 재지 않았다(11장에서 잰다).

### 6.2 자리 나누기와 칸 수

- **패드의 폭은 자판 폭 W**다(SRS FR-CMN-14 ④·⑥). 양쪽 여유 칸은 패드에 들지 않는다.
- **문자 칸은 왼쪽부터** 틈 없이 놓고, **숫자 영역은 오른쪽 나머지 폭 전부**다. 숫자 영역은 칸이 아니고 폭이 고정되지 않는다. 숫자 영역에 최대 폭을 두지 않는다(넓은 화면에서 지나치게 넓은지는 실기기에서 본다).
- **들어가는 칸 수** = (W − 숫자 영역 최소 폭) ÷ 칸 폭(3h)을 내림한 값이고, 1보다 작으면 1이다.
- **숫자 영역 최소 폭**의 시작값은 **90dp**다(12장 V6). 실제로 써 온 폭으로 확인된 것은 좌우 여유 칸이 들어오기 전 기본 설정의 120dp뿐이고, 90dp는 그때 설정에서 고를 수 있던 가장 좁은 폭이다. 90dp보다 좁은 폭에 숫자를 쓸 수 있는지는 미확인이다.
- **칸 수 설정**: 저장값은 1~4, 기본값은 2다. **실제 칸 수 = 저장값과 들어가는 칸 수 중 작은 값**이다. 넘는 값을 골라도 저장값은 그대로 두고, 그 화면에 들어가는 만큼만 쓴다(자판 폭 설정의 "꽉 채움"과 같은 방식). 세로·가로 화면에 설정을 따로 두지 않는다. 값의 범위와 기본값은 오너가 정한다(13장 3번).

> 오너 결정(2026-11-13, FSS#83, "권장안대로 진행하자"의 1번): 폰 세로 구성은 한 칸 + 넓은 숫자 영역으로 시작한다(두 칸 + 좁은 숫자 영역은 시제품에서 비교).

**셈(기본 줄 높이 48dp, 칸 폭 144dp, 숫자 영역 최소 폭 90dp, SRS FR-CMN-14의 식으로 한 것이고 기기에서 재지 않았다).**

| 화면과 자판 폭 설정 | 가용 폭 A | 키 한 칸 u | 자판 폭 W = 10u | 들어가는 칸 수 | 기본값(2)일 때 | 숫자 영역 폭 |
|---|---|---|---|---|---|---|
| 폰 세로, 꽉 채움 | 360dp | 약 32.7dp | 약 327.3dp | 1 | **한 칸** | 약 183.3dp |
| 폰 세로, 꽉 채움 | 411dp | 약 37.4dp | 약 373.6dp | 1 | 한 칸 | 약 229.6dp |
| 폰 세로, 키 크기 하한 | 360dp | 32dp | 320dp | 1 | 한 칸 | 176dp |
| 폰 가로, 기본(세로와 같은 키 크기) | 711dp | 약 32.7dp | 약 327.3dp | 1 | 한 칸 | 약 183.3dp |
| 폰 가로, 꽉 채움 | 711dp | 약 64.6dp | 약 646.4dp | 3 | 두 칸 | 약 358.4dp(세 칸이면 약 214.4dp) |

- **폰 세로는 한 칸 + 숫자 영역으로 시작하고, 두 칸 + 좁은 숫자 영역은 시제품에서 비교한다**(위 오너 결정 그대로).
- 비교에 쓸 셈(사실, 기기에서 재지 않음): 좌우 여유 칸(FSS#84) 뒤로 360dp 세로 화면의 자판 폭은 약 327.3dp라, 기본 줄 높이에서 두 칸(288dp)을 놓으면 **숫자 영역이 약 39.3dp**다. 411dp 화면이면 약 85.6dp, 360dp 화면에서 줄 높이 40dp(칸 120 × 160dp)면 약 87.3dp다. 셋 모두 숫자 영역 최소 폭의 시작값 90dp보다 좁아, 위의 "들어가는 칸 수" 셈대로면 칸 수 설정을 2로 해도 폰 세로는 한 칸이 된다. 90dp보다 좁은 숫자 영역에 숫자를 쓸 수 있는지는 미확인이다(14장 8번).
- 그래서 **비교를 어떤 조건에서 할지**(줄 높이, 비교하는 동안 숫자 영역 최소 폭을 어떻게 둘지, 견줄 화면)를 오너에게 묻는다(13장 3번, SRS TBD-42). 비교 조건이 정해지기 전에도 기본 동작은 한 칸이다.
- 폰 가로는 기본 설정(세로와 같은 키 크기)에서 자판 폭이 세로와 같으므로 칸 수도 세로와 같다. 가로에서 자판을 넓힌 경우에만 칸이 더 들어간다.
- 줄 높이를 바꾸면 칸도 함께 변한다: 폰 세로(W 약 327.3dp)에서 h 40dp면 한 칸(숫자 약 207.3dp), h 64dp면 한 칸(숫자 약 135.3dp)이다.
- 화면 폭 360dp 이상(SRS AS-1)이면 한 칸은 늘 들어가고 숫자 영역이 최소 폭 이상이다(가장 좁은 경우: W 320dp, h 64dp, 숫자 128dp).
- 지금의 영역 폭 비율 설정(SRS FR-SET-05, 1 : 1 / 2 : 1 / 3 : 1)은 문자 쪽 폭이 칸 수 × 칸 폭으로 정해지므로 뜻이 없어진다. 정해질 때까지의 기준으로 칸 수 설정이 그 자리를 대신한다(13장 3번).

### 6.3 그리기

- **문자 칸마다 테두리를 실선**으로 그린다. 칸이 둘이면 같은 크기의 사각 둘을 나란히 그린다.
- **한글 상태의 문자 칸에는 칸을 넷으로 나누는 선(가로·세로 가운데)을 점선**으로 그린다(오너 결정). 한글이 새 방식이 되는 2단계부터 그린다. 그 전의 한글 상태(한 획 약속 글자)에서는 사분 자리에 뜻이 없어 그리지 않는다.
- **영문 상태의 문자 칸에는 기준선 둘을 가로 점선**으로 그린다(정해질 때까지의 기준, 13장 6번).
- 숫자 영역은 지금처럼 경계 사각형과 흐린 "123"을 그린다.
- 선은 **쓰는 자리를 잡는 안내**다. 선에 맞추려다 글씨가 어색해지는지는 미측정이다. 가로 모음 + 받침 꼴처럼 세 층인 음절은 십자선과 맞지 않는다(7.1절).
- 언어 글자("한" / "A")와 구석 탭 영역은 **첫 문자 칸의 왼쪽 위 구석**에 둔다. 대기 표시(⇧·⇪·•·↘)의 자리는 선·글씨와 겹치지 않게 LLD에서 정한다.
- 선의 두께·색·점선 간격은 LLD에서 정한다. 비밀번호·학습 금지 입력창에서도 그린다(입력 글자가 아니다).

### 6.4 여러 칸의 동작

| 경우 | 규칙 | 근거 |
|---|---|---|
| 획이 어느 칸의 것인가 | **시작점의 칸.** 획이 경계를 넘어가도 바뀌지 않는다 | 지금 영역 판정과 같다 |
| 지금 열린 칸이 아닌 칸에서 획이 시작됨 | **앞 칸의 묶음을 마무리**(글자면 확정)하고 새 칸에서 새 글자를 시작한다 | 칸 이동이 확정 신호다 |
| 칸을 건너뛰거나 거꾸로 씀 | **차례를 강제하지 않는다.** 글자는 칸의 자리가 아니라 쓴 차례대로 들어간다 | 규칙이 위의 하나로 끝난다 |
| 앞 칸으로 돌아가 덧씀 | **새 글자다.** 닫힌 글자를 다시 열지 않는다. 고치려면 ⌫를 쓴다 | 2.4절 |
| 칸을 다 썼을 때 | **첫 칸으로 돌아가 쓴다.** 쓴 것을 옆으로 밀지 않는다. 두 칸이면 번갈아 쓰기가 된다. 사용자가 돌아가 쓰는 것이고, 자동으로 움직이는 커서나 "다음 칸" 표시는 없다(시스템은 칸의 차례를 따로 기억하지 않고 위 두 줄의 규칙으로 처리한다) | 오너 결정(FSS#83, "권장안대로"의 2번) |
| 숫자 영역에서 획이 시작됨 | 문자 칸의 열린 묶음을 마무리하고 숫자 영역 획으로 처리한다 | 지금의 "조합을 먼저 확정"과 같다 |

- 한 칸뿐이면 칸 이동이 없으므로 글자의 끝은 자람 원칙과 글자 닫기 동작으로만 정해진다.
- 옛 방식이 유효한 구간(11장)에서는 **문자 칸 전체를 지금의 문자 영역 하나로 본다.** 칸을 옮겨도 확정이 일어나지 않고, 획 자국도 남기지 않는다.
- **미확인:** 이때 문자 영역(칸 전체)과 숫자 영역의 크기·가로세로 비율이 지금과 달라진다(폰 세로 기본에서 문자 쪽 144 × 192dp, 숫자 영역 약 183.3dp 폭). 옛 약속 획 인식(한글, 대문자, 숫자·기호)이 영역의 크기나 비율에 기대는지, 그래서 같은 획의 결과가 바뀌는지는 확인하지 않았다(14장 15번).

### 6.5 획 자국

- **열린 묶음의 획은 닫힐 때까지 패드에 그대로 보인다.** 앞 획이 보여야 다음 획의 자리를 잡는다.
- **확정된 칸의 자국은 흐리게 남기고, 그 칸에 새 획이 시작될 때 지운다**(오너 결정, FSS#83 "권장안대로"의 3번). 한 칸뿐이면 새 글자의 첫 획이 시작될 때 앞 글자의 자국이 지워진다.
- 글자가 되지 못하고 버려진 획의 자국은 남기지 않는다.
- 키보드가 내려가거나 그래피티 모드를 떠나면 자국을 모두 지운다.
- **지금의 잉크 선과의 관계:** 획을 긋는 동안은 지금처럼 패드의 잉크 선으로 그린다. 지금은 손을 떼면 잉크 선을 지우는데, 새 방식 구간에서는 손을 뗀 그 선을 지우지 않고 획 자국으로 남긴다(같은 선이고 따로 더 그리지 않는다). 옛 방식 구간의 잉크 선은 지금 그대로다. 긋기 자판의 획 자국(SRS FR-DSP-09)과 그 설정(FR-SET-02)은 패드와 상관없다.
- 비밀번호 입력창에서 자국을 어떻게 할지는 오너가 정한다(13장 10번). 정해질 때까지의 기준: 열린 묶음의 자국은 보이고(안 보이면 여러 획 글자를 쓸 수 없다), 확정된 칸의 흐린 자국은 남기지 않는다.

## 7. 한글 (2단계)

**이 장의 표와 판단은 손으로 만든 것이고 사람 획으로 재지 않았다.** 2단계 설계에서 수집 결과로 다시 본다.

### 7.1 음절 꼴마다 자모가 놓이는 자리

| 꼴 | 예 | 초성 | 중성 | 종성 | 사분으로 갈리는가 |
|---|---|---|---|---|---|
| 세로 모음, 받침 없음 | 가, 너, 비 | 왼쪽 절반 | 오른쪽 절반 | – | 좌우로 갈린다 |
| 가로 모음, 받침 없음 | 고, 누, 그 | 위 절반 | 아래 절반 | – | 위아래로 갈린다 |
| 섞인 모음, 받침 없음 | 과, 뭐, 의 | 왼위 | 가로 부분은 왼아래, 세로 부분은 오른쪽 절반 | – | 갈린다. 모음이 두 군데에 놓인다 |
| 세로 모음 + 받침 | 각, 넌, 밥 | 왼위 | 오위 | 아래 절반 | 칸마다 자모 하나 |
| 가로 모음 + 받침 | 곡, 눈, 음 | 위 | 가운데(위아래 경계 위) | 아래 | **걸친다.** 세 층이라 2 × 2에 맞지 않는다 |
| 섞인 모음 + 받침 | 곽, 원, 흰 | 왼위 | 가로 부분은 왼쪽 가운데, 세로 부분은 오위 | 아래 절반 | **걸친다** |

- 같은 자모가 꼴에 따라 다른 자리에 놓인다("가"의 ㄱ은 왼쪽 절반 전체, "각"의 ㄱ은 왼위). 쓰는 중에는 받침이 올지 알 수 없다.
- 그래서 사분 자리는 "획이 어느 자리 하나에 있는가"가 아니라 **"주로 어느 쪽(위 / 아래, 왼쪽 / 오른쪽)에 있는가"**로 쓴다.
- **자리로 정해지는 것**: 첫 획이 왼위나 위에서 시작하면 초성, 오른쪽 절반의 세로획은 세로 모음, 아래 절반의 자음 획은 받침.
- **자리만으로 안 정해지는 것**: 한 자모 안의 획 관계(5.2절), 가로 모음과 받침의 위아래(둘 다 아래 절반에 올 수 있다).

### 7.2 경계에 걸친 획의 판정

- 획의 길이가 네 자리에 얼마씩 놓였는지(**자리별 길이** 네 값)로 "주로 어느 쪽"을 정한다. 시작점은 필순(위에서 아래로, 왼쪽에서 오른쪽으로) 확인에 쓴다.
- 시작점 하나나 획 둘레의 가운데 하나로 정하지 않는다(긴 획의 나머지를 모르거나, 걸친 획이 경계선 위에 떨어져 가장 애매한 값이 된다).
- 경계 근처의 기준값은 사람 획으로 정한다(12장 V7).

### 7.3 한 칸 안에서 음절이 끝난 것을 아는 방법

1. **자모는 다음 자모가 시작되면 닫힌다.** 초성 → 중성 → 종성 차례로만 자란다. 모음을 쓴 뒤 위쪽에 온 가로획은 닫힌 초성 ㄱ에 붙어 ㅋ이 되지 못한다.
2. **새 획이 지금 음절의 어느 열린 자모에도 붙지 않고, 받침 자리(지금 모음보다 아래)도 아니면 새 음절이다.**
3. 새 음절이 시작되면 앞 음절을 확정한다.
- 초성만 있고 모음이 없는 묶음 뒤의 새 초성은 낱자 입력이다(ㅋㅋ, ㅇㅇ).
- 받침 없는 음절 뒤에서 다음 초성을 조금 아래에 쓰면 받침으로 붙을 수 있다. 가운데에 쓴 획의 오류율은 미측정이다. 칸이 둘 이상이면 다음 음절을 다른 칸에 써서 피한다.

**앞서 걸린 쌍(손으로 한 판단).**

| 쌍 | 가르는 수단 |
|---|---|
| ㅋ과 "그" | 가로가 ㄱ 둘레 안인가 아래인가(5.2절) |
| "구"와 "긔" | 세로가 가로 아래에서 내려가는가, 오른쪽에서 솟는가(5.2절) |
| "는"과 ㄴㄷ | 초성 ㄴ 뒤의 가로는 모음 ㅡ다(차례). 그 뒤 아래의 ㄴ 꼴은 받침이다 |
| ㅗ 모양 + ㅇ("공")과 ㅎ | 초성이 있으면 ㅗ 모양은 모음, 아래의 ㅇ은 받침이다. 초성이 없으면 차례로 가른다 |
| 받침과 다음 음절의 초성 | 받침은 지금 모음보다 아래, 새 초성은 왼위. 가로 모음 꼴은 "ㅡ보다 아래인가"를 본다(미측정) |

### 7.4 조합기와의 연결

- 획이 자모로 자라고(ㄱ → ㅋ), 자모가 음절로 자란다(ㄱ → 가 → 각). 뒤 층은 지금 조합기(`core-hangul`)가 한다. 손글씨 쪽은 자모와 그 자리(초성 / 중성 / 종성)를 조합기에 넘긴다.
- **자리가 받침과 초성을 정하므로** 받침으로 붙였다가 모음이 오면 다음 음절로 넘기는 처리(도깨비불)가 손글씨에서는 일어나지 않게 한다. 새 음절이 시작되면 앞 음절을 먼저 확정해 넘긴다.
- **천지인 요소(세로선, 가로선, 탭으로 모음을 만드는 것)는 그래피티에서 없어진다.** 모음도 글자 모양대로 쓴다. 천지인 조립기는 긋기 자판의 천지인 키가 계속 쓴다(SRS FR-SWP-62). 이것은 PM 판단이고 오너 확인 항목이다(13장 9번).
- 쌍자음은 지금처럼 시프트 + 자음이다. ㄱ을 두 번 쓰면 ㄲ인지 받침 ㄱ + 초성 ㄱ인지 가를 수 없다.

## 8. 입력 구분과 제어

### 8.1 남는 것

| 기능 | 새 방식에서 |
|---|---|
| 한영 전환 | 구석 탭 그대로. 구석 탭 영역은 첫 문자 칸의 왼쪽 위다 |
| 시프트, 캡스록 | 아래 → 위 세로 획 그대로(한 번 = 시프트, 영문에서 두 번 = 캡스록). 방향이 글자 획과 반대라 겹치지 않는다 |
| 숫자 영역 | 그대로. 모드와 상관없이 숫자·기호다 |
| 기호 대기 | 탭 뒤의 획 그대로(영문 상태: 두 영역의 탭, 한글 상태: 숫자 영역의 탭). 글자의 점과 가르는 규칙은 8.5절 |
| 쌍자음 | 시프트 + 자음 그대로 |
| ⌫ 획 | 오른쪽 → 왼쪽 가로 그대로. 열린 묶음에서는 마지막 획을 되돌린다(8.3절) |

### 8.2 제어 획과 글자 획이 겹치지 않는 까닭

- ⌫ 획(←)과 시프트 획(↑)은 **방향이 글자 획과 반대**다(3장). 그래서 남긴다.
- 스페이스 획(→, V), 리턴 획(↙), 확장 시프트 획(↘), 확정 획(J)은 **글자의 획과 같아진다**(→는 가로, V는 v, ↙는 ／, ↘는 ＼, J는 j). 그래서 새 방식 구간(문자 칸)에서는 획으로 받지 않는다.
- **숫자 영역은 그 단계가 올 때까지 지금 규칙 그대로다.** 숫자 영역에서 그은 →(스페이스), ↙(리턴), ↘(확장 시프트)는 3단계까지 지금처럼 동작한다. 숫자 영역의 획을 따로 고치지 않으려는 것이다.

### 8.3 ⌫

- **열린 묶음이 있으면 마지막 획 하나를 되돌리고 남은 획으로 다시 판정한다**(⌫ 버튼과 ⌫ 획 모두). 획이 남지 않으면 묶음이 없어진다. 패드의 자국도 그 획만 지운다.
- 열린 묶음이 없으면 지금 규칙대로다(확정된 글자 한 글자, 한글 조합 중이면 입력 단위 하나, SRS FR-CMN-07).
- **끝 글자는 완성되는 자리에서 확정되므로**, 그 뒤의 ⌫는 그 글자 한 글자를 지운다(t를 쓴 뒤 ⌫ = t가 지워짐. l로 돌아가지 않는다). 1단계에서 열린 묶음은 늘 획 하나라(4.1절), 열린 묶음의 ⌫는 그 묶음을 없앤다(l ⌫ = 빈 상태).
- 2단계의 한글은 자모가 닫혀도 음절이 조합 중이므로, 조합 중인 음절 안에서는 그은 차례의 거꾸로 획 하나씩 되돌린다(ㅐ ⌫ = ㅏ). 세부는 2단계 설계에서 정한다.

### 8.4 글자 닫기, 스페이스, 리턴

> 오너 결정(2026-11-13, FSS#83, "권장안대로 진행하자"의 5·6번): 글자 닫기 동작을 둔다. 스페이스·리턴은 버튼으로 한다.

- **글자 닫기 동작**: 열린 묶음을 지금 상태로 마무리한다(글자면 확정, 앞부분이면 버림). 글자를 넣지 않는다. 잘못 붙는 것을 막거나(한 칸에서 c 다음 l을 쓰기 전에), 열린 글자를 굳힐 때 쓴다. 무엇으로 할지는 오너가 정한다(13장 1번). 정해질 때까지의 기준: **보조 줄에 [닫기] 버튼**을 둔다.
- 한글에서 글자 닫기는 지금의 확정 획(J)이 하던 일(조합 강제 확정)을 한다.
- **스페이스·리턴은 보조 줄 버튼으로** 넣는다. 새 방식 구간의 문자 칸에서는 스페이스 획·리턴 획을 받지 않는다(숫자 영역의 획은 8.2절대로 3단계까지 남는다). 버튼을 누르면 열린 묶음을 먼저 마무리한다.
- 시간이 지나서 닫히는 일은 없다.

### 8.5 탭

탭은 아래 차례로 본다.

1. **글자의 점**: 열린 묶음이 점을 받을 수 있는 상태(1단계: l, 내림 갈고리. 2단계: 한글에서는 탭이 묶음의 첫 획일 수도 있다 — ㅊ·ㅎ의 꼭지)이고 자리 조건(P3)이 맞으면 점이다.
2. **한영 전환**: 1이 아니고 구석 탭 영역 안이면 한영 전환이다.
3. **기호 대기**: 1·2가 아니고 그 언어 상태에서 기호 대기를 만드는 영역의 탭이면 기호 대기다.

- 그래서 기호 대기의 탭을 l 바로 위에 찍으면 i가 된다. 헷갈리는 횟수를 1단계에서 잰다.
- 2단계에서 ㅊ·ㅎ의 꼭지 점(음절의 첫 획)이 구석 탭 영역에 떨어지면 한영 전환과 겹친다. 구석 탭 영역의 자리와 크기를 2단계 설계에서 다시 정한다(12장 V8).

### 8.6 확장 시프트와 "사선 + 탭" 한영 전환

- 확장 시프트 획(↘)은 ＼(x·y의 첫 획, ㅅ의 둘째 획)와 같다. 새 자리는 오너가 정한다(13장 2번).
- 정해질 때까지의 기준: **새 방식 구간의 문자 칸에서는 ↘를 글자의 획으로 본다. 확장 시프트는 숫자 영역에서 그은 ↘로 넣는다**(숫자 영역은 그 단계가 올 때까지 지금 규칙 그대로라 새 동작이 필요 없다). "사선 + 가운데 탭" 한영 전환도 숫자 영역에서 그은 사선 뒤의 탭으로만 된다.
- 그 탭의 자리: **보지 않는다.** 지금도 "가운데 탭"은 위치를 보지 않고 "사선 다음이 탭"이면 한영 전환이다. 숫자 영역의 사선으로 확장 시프트 대기가 켜지면 다음 획은 옛 방식으로 인식하므로(11장 표, SRS FR-HWR-144) 문자 칸이든 숫자 영역이든 어디의 탭이어도 한영 전환이다. 문자 칸에서 그은 ↘는 글자의 획이라 대기를 켜지 않으므로, 그 뒤의 탭은 8.5절의 차례대로 본다.

## 9. 표시와 피드백

### 9.1 조합 중 글자

- 열린 묶음이 **글자**면 조합 중 글자로 입력창에 보이고, 자라면 갈아 끼운다(l → t).
- 열린 묶음이 **앞부분**이면 입력창에는 아무것도 더 보이지 않고(마지막으로 글자였던 것이 있으면 그것만), 패드에 획 자국이 남는다.
- 끝 글자는 완성되는 자리에서 확정되어 조합 표시 없이 들어간다.

### 9.2 인식 글자 표시

- 새 방식 구간에서는 지금의 "인식한 글자를 획 직후 잠깐 보임"(SRS FR-GRF-07)을 쓰지 않는다. 조합 중 글자와 패드의 획 자국이 그 자리를 대신한다.
- 옛 방식이 유효한 구간(숫자 영역, 기호 대기 뒤의 획 등)은 지금대로 보인다.

### 9.3 오류 진동

- **새 글자의 시작으로도 아무것도 아닌 획**에 낸다(열린 묶음에 붙지도 않고 첫 획으로도 표에 없는 획). 입력은 없다.
- 열린 묶음에 붙지 않아 **새 글자를 시작한 획에는 내지 않는다**(지금의 조립 닫기와 달라지는 점이다).
- **글자가 되지 못한 채 버려지는 앞부분**(가로를 긋지 않은 갈고리 세로 등)이 패드·보조 줄 입력(새 획, 닫기, 스페이스, 리턴, 제어 획) 때문에 버려질 때도 낸다. 쓰던 획이 말없이 사라지지 않게 하려는 설계 기준이다(13장 13번). 모드 전환·커서 이동·입력창 변경·키보드 내려감으로 버려질 때는 내지 않는다.

## 10. 판정 방법과 갈아 끼울 자리

> 오너 결정(2026-11-13, FSS#83, "권장안대로 진행하자"의 4번): 판정 방법은 획 차례 표 + 자리 규칙으로 시작한다. 묶음 전체 인식은 자료가 모이면 같은 획으로 비교한다.

- 시작하는 방법: 획마다 기본 획·한 획 글자로 분류하고(3장), 자람 표에서 다음 상태를 찾고(4장), 자리 규칙으로 가른다(5장).
- 나중에 비교할 방법: 획이 올 때마다 묶음 전체를 인식기에 넣어 글자 / 앞부분 / 아님을 받는다. 여러 획 글자의 사람 자료가 있어야 만들 수 있다.
- **어느 쪽이 나은지는 재지 않았다.** 두 방법이 같은 물음("이 묶음 + 새 획은 글자인가, 앞부분인가, 아닌가")에 답하므로, 판정부를 갈아 끼울 수 있게 두고 같은 획 기록으로 비교한다(HLD 5B장).
- 어느 방법이든 같은 입력에는 늘 같은 결과를 낸다(SRS NFR-04).
- 한 획 글자의 입력 표현(격자 / 점 열 / 템플릿)을 견준 값은 한 획 약속 글자 자료(한 사람)로 잰 것이다(FSS#82). **여러 획 글자의 값이 아니다.** 여러 획 글자의 인식 정확도는 어느 방식도 재지 않았다.

## 11. 단계

| 단계 | 범위 | 새 방식 구간 | 그동안 옛 방식이 유효한 곳 |
|---|---|---|---|
| **1단계** | 영문 소문자 + 칸 | 영문 상태의 문자 칸, 시프트 대기·캡스록·기호 대기·확장 시프트 대기가 모두 없을 때 | 한글 상태 전체, 영문 대문자(시프트·캡스록 상태의 획), 숫자 영역, 기호 대기·확장 시프트 대기 뒤의 획 |
| **2단계** | 한글 음절 | + 한글 상태의 문자 칸(같은 대기 조건) | 영문 대문자, 숫자 영역, 기호 대기·확장 시프트 대기 뒤의 획 |
| **그 뒤(3단계)** | 대문자·숫자·기호 정리, 수집과 묶음 전체 인식 비교 | 3단계 설계에서 정한다 | – |

- 1단계 내용: 칸 배치와 칸 수 설정, 획 차례 표 + 자리 규칙(4.1·5.1절), 조합 중 글자 표시, 획 자국, ⌫ 되돌림, 글자 닫기, 스페이스·리턴 버튼, 획 기록(디버그 빌드, 11.2절의 수집 수단).
- 2단계 내용: 사분 자리(7장), 한글 자모 자람 표(4.5·4.6절), 조합기 연결, 천지인 요소 제거, 사분 점선.
- **옮겨 가는 동안**: 1단계가 들어가도 한글·대문자·숫자·기호는 그 단계가 올 때까지 지금 약속 획 요구사항이 그대로 유효하다. 항목별 표는 SRS 3.7A.1에 있다. 다만 그 획이 칸 모양의 영역에서 지금과 같은 결과를 내는지는 미확인이다(6.4절, 14장 15번).
- 1단계를 디버그 전용으로 켤지 정식 동작으로 바꿀지는 오너가 정한다(13장 4번). 정해질 때까지의 기준: **디버그 빌드에서만 켜는 스위치**로 넣고, 끄면 지금 동작 그대로다.
- 영문 대문자를 옛 획으로 두는 동안, 소문자는 평소 모양으로 쓰고 대문자는 시프트 뒤 약속 획으로 쓰게 된다. 시프트 뒤에도 소문자 모양을 쓰고 대문자가 들어가게 하는 안을 13장 4번에 함께 올린다.

### 11.1 단계마다 잴 것

**1단계(영문 소문자).**
1. 낱말 입력의 오류를 종류별로: 글자 오인식 / 두 글자가 붙음 / 한 글자가 끊김 / 나중에 찍은 획.
2. 붙는 쌍이 든 낱말(the, child, clock, old, hello, little, fix, joy 등)에서의 오류.
3. 글자당 획 수와 입력 시간. 지금 그래피티 영문과 같은 문장으로 견준다.
4. 기본 획과 한 획 글자의 인식 정확도.
5. 폰에서의 인식 시간.
6. i의 점과 기호 대기 탭이 헷갈리는 횟수.
7. 칸 크기(144 × 192dp)가 쓰기에 맞는지, 기준선에 맞춰 쓴 높이로 l·i의 앞부분과 대소문자를 가를 수 있는지.

**2단계(한글 음절).**
1. 음절 꼴(7.1절의 여섯)별 자모의 자리별 길이 분포.
2. 받침과 다음 초성의 세로 자리 분포(기준값과 오류율), 받침 없는 글자를 칸의 어디에 쓰는가.
3. 사람들의 실제 획 차례가 자람 표와 얼마나 맞는가.
4. 한 칸과 두 칸에서 같은 문장의 오류와 시간.
5. 같은 문장을 지금 그래피티·두벌식과 새 방식으로 넣을 때의 속도와 고친 횟수.

**그 뒤.**
1. 묶음 전체 인식과 표 방식을 같은 획으로 견준 정확도.
2. 다른 사람의 글씨에서의 정확도(다른 사람의 글씨를 모을지는 13장 11번).

### 11.2 단계마다 모을 획

| 단계 | 묶음 | 내용 | 재는 것 |
|---|---|---|---|
| 1 | 낱자 | 소문자 26 × 5번 | 글자별 획 수·차례의 분포(두 획으로 쓰는 사람의 비율), 한 획 글자의 모양 |
| 1 | 낱말 | 붙는 쌍이 든 낱말 30개 안팎을 평소처럼 | 나중에 찍는 획의 빈도, 글자 사이 닿음, 자리 기준값 V1~V3 |
| 1 | 칸 조건 | 같은 낱말을 한 칸에 겹쳐서 / 두 칸에 번갈아 | 칸 이동으로 붙는 쌍이 풀리는지 |
| 2 | 음절 | 여섯 꼴이 고루 나오게 짠 음절 목록을 칸에 쓰기. 한 칸과 두 칸 두 조건 | 11.1의 2단계 1~4 |
| 2 | 자모 낱자 | 자음 14 + 모음 21 × 5번 | 획 수·차례의 분포 |
| 3 | 대문자·숫자·기호 낱자 | 3단계 설계에서 정한다 | – |

- 획마다 좌표와 시각, 시작한 칸을 남긴다. **릴리스 빌드는 획을 기록하지 않는다**(SRS NFR-05 그대로). 수집은 디버그 빌드의 기록 기능으로 한다(SRS FR-HWR-180, 1단계에 함께 들어간다).
- 사람 수는 오너가 정한다(13장 11번). 정해질 때까지는 오너의 획만 모은다.
- 지금 가진 오너의 한 획 자료는 약속 모양이다. 약속 모양이 평소 모양과 같은 글자에만 다시 쓸 수 있고, 어느 글자가 그런지는 확인하지 않았다.
- 공개 자료: 영문 소문자 낱자의 획 좌표가 든 UJI Pen Characters v2(60명)가 있고, 이용 조건은 원문으로 확인했다(CC BY 4.0, 출처 표기). 펜으로 쓴 자료이고 시각이 없다. 한글의 획 좌표 공개 자료는 찾지 못했다.

## 13. 오너가 정할 것

정해질 때까지 **굵게 적은 권장안을 기준으로** 문서를 쓰고 진행한다. 번호 옆은 SRS 7장의 TBD 번호다.

| 번호 | 정할 것 | 비교안 | 권장(정해질 때까지의 기준) |
|---|---|---|---|
| 1 (TBD-40) | 글자 닫기 동작을 무엇으로 할지 | 가. 보조 줄에 [닫기] 버튼 / 나. 패드의 한 동작(숫자 영역 탭, 두 손가락 탭 등) / 다. 여러 칸일 때 다른 칸 탭 | **가.** 패드의 동작은 글자의 점·기호 대기 탭과 겹친다. 버튼은 겹치지 않고 눈에 보인다. 보조 줄 버튼이 넷으로 늘어 폭이 준다(폰 세로 약 85dp → 약 64dp) |

| 3 (TBD-42) | 칸 수 설정의 값과 기본값, 숫자 영역 최소 폭, 영역 폭 비율 설정(FR-SET-05)을 없앨지, **폰 세로 "두 칸 + 좁은 숫자 영역"의 시제품 비교를 어떤 조건에서 할지**(비교하는 것은 오너 결정, FSS#83 "권장안대로"의 1번) | 값: 1~4 / 1~2 / 자동. 기본: 2 / 1. 최소 폭: 90dp / 72dp. 비율 설정: 없앰 / 남김. 비교 조건(6.2절의 셈: 360dp 세로 화면에서 두 칸이면 숫자 영역이 기본 줄 높이 약 39.3dp, 줄 높이 40dp 약 87.3dp, 411dp 화면 기본 줄 높이 약 85.6dp): 가. 기본 줄 높이에서, 비교하는 동안만 숫자 영역 최소 폭을 적용하지 않음(숫자 영역 약 39.3dp) / 나. 줄 높이 40dp에서, 비교하는 동안만 최소 폭을 적용하지 않음(약 87.3dp) / 다. 숫자 영역 최소 폭을 낮춰 정식 셈으로 두 칸이 들어가게 함(얼마로 낮출지 함께 정함) | **1~4, 기본 2(들어가는 만큼만 씀), 최소 폭 90dp, 비율 설정은 없앰. 비교 조건은 가와 나를 디버그 빌드에서 함께 견준다.** 다를 고르면 숫자 인식을 재기 전에 정식 셈(최소 폭)을 바꾼다. 어느 조건이든 비교 전과 비교 동안의 기본 동작은 한 칸이다 |
