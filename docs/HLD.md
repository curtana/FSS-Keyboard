- 문서: HLD, 버전 **0.64** (2026-11-02)
- 상태: 초안. LLD 0.1이 올린 설계 변경 요청 DCR-01~21(오너 승인 2026-10-27)을 반영했다.
- 요구사항: [SRS.md](SRS.md) 0.71
- 상세 규칙: [SWIPE_INPUT_DESIGN.md](SWIPE_INPUT_DESIGN.md) 0.51, 그래피티 규칙 문서(비공개, `docs-private/GRAFFITI_FEASIBILITY.md` — 저장소에 올리지 않음, 이슈 #249. 아래의 "GRAFFITI n.n"은 이 문서의 절)

## 1. 설계 원칙

| 원칙 | 내용 | 관련 요구 |
|---|---|---|
| 순수 엔진 분리 | 판정·조합·인식(천지인 조립 포함)은 안드로이드 없는 Kotlin 모듈로 만든다. 앱은 터치를 모아 엔진에 넘기고 결과를 입력창에 쓰기만 한다 | NFR-08 |
| 결정성 | 엔진은 (점 열, 시각, 키 사각형, 기준값, 매개변수로 받은 상태)만 보고 결과를 낸다. 실제 시계·전역 상태를 직접 읽지 않는다 | NFR-04 |
| 데이터로 정의 | 자판 배치, 숫자·기호 배치표, 모음 병합 표(입력 방식별), 그래피티 템플릿은 데이터(Kotlin 상수 표·JSON)로 둔다 | 변경 용이 |
| 실패해도 입력기는 산다 | 엔진 예외는 획 단위로 잡아 무시하고, 입력 내용 없이 기록한다 | NFR-03, NFR-05 |
| 표시와 판정 분리 | 안내 표시는 엔진의 "진행 중 상태"를 그리기만 하고, 판정에 관여하지 않는다 | FR-DSP-06 |

**의존 방향:** `app` → `stroke-core`, `core-hangul`, `recognizer`, `gesture-engine`. `gesture-engine` → `stroke-core`. `gesture-engine`과 `recognizer`는 `core-hangul`의 **자모 정의와 이벤트 형식**, 그리고 **천지인 조립(`CheonjiinAssembler`)**만 참조한다(조립기는 이슈 #160로 core-hangul에 두고 둘이 함께 씀). 조립기 객체(상태)는 쓰는 쪽이 하나씩 가진다: 그래피티는 앱의 그래피티 입력 처리부, 긋기는 `SwipeInputMapper`(기준 키·쌍자음 후보와 함께, 4.3). (0.27까지 `BlockParser`가 쓰던 긋기 병합 표 참조(DCR-15)는 이슈 #150로 필요 없어졌다. 나눠 쓰기 병합은 조합기 정책이 정한다, 4.4.) 조합 상태는 앱이 가진 조합기 하나에 있고, 엔진이 필요한 상태는 호출할 때 매개변수로 받는다(이슈 #173로 기준 키가 없어짐).

## 4. 긋기 입력 처리 흐름

### 4.1 한 획의 흐름

```
MotionEvent
   │ ACTION_DOWN: 키 찾기(이웃 틈은 가까운 키로), 획 시작, 누른 시각 기록
   │              안내용으로 SwipeInputMapper의 조립 상태를 읽음(6장: 이어 그을 수 있는 획)
   ▼
TouchTracker ── 포인터 ID별 추적. 획 진행 중의 다른 포인터는 무시(FR-CMN-11)
   │ ACTION_MOVE 마다: 히스토리 점까지 (x, y, t) 누적
   ▼
StrokeClassifier.update(point)  ──►  ProgressState (지금 떼면 될 획 종류·조립 결과)
   │                                    ▼
   │                               GuideOverlay.render()
   │ ACTION_UP
   ▼
StrokeClassifier.finish()  ──►  StrokeResult(결과 = 탭 / 모음 획(세로·가로, 시작점·끝점) / 반대 방향 / 숫자·기호, 누른 시각, 뗀 시각)
   ▼
SwipeInputMapper.accept(StrokeResult, key)  ──►  JamoEvent 목록 | 무시(반대 방향·이어질 수 없는 획, 오류 진동) | 문자(숫자·기호)
   ▼
HangulComposer (core-hangul, 긋기 정책: 두벌식 조합·빈 모음 병합 표·자모·획 단위 백스페이스)  ──►  (확정 텍스트, 조합 텍스트)
   ▼
ComposingController ──► InputConnection
```

- **ACTION_CANCEL**(플랫폼이 터치를 취소): 진행 중인 획을 결과 없이 버리고 안내 표시를 닫는다. 기능키 반복은 멈춘다(SRS FR-CMN-11a, DCR-11). 모든 입력 뷰(탭 자판, 긋기 자판, 그래피티 패드)에 같다.
- **긋기 자판의 기능키**(⌫, ↵, 스페이스, 모드 키)와 빈 칸은 모음 획 판정에 들어가지 않는다(설정 키는 이슈 #205로 삭제, 그 자리는 이슈 #208로 기호3 키). 기능키는 누를 때 처리하고(FR-CMN-11a), 모드 키만 손을 뗄 때 탭 / ↑를 가른다(SRS FR-CMN-13, 8.2절). 빈 칸은 터치만 받고 입력이 없다(FR-SWP-50, DCR-03). 기능키는 `SwipeInputMapper`에 알려 조립을 닫는다(4.3).

### 4.2 StrokeClassifier: 획 판정 (gesture-engine)

**입력:** 키 사각형, 키 종류(**한글 자음 / 천지인 / 둘레 숫자 / 기호**), 사용 가능 방향, 기준값, 점 열, **가운데 자음 자리 C**(경계 상자, 조합 중 자음이 있을 때만 — 모음 판정 기준, SRS FR-SWP-19·TBD-24. 자판 배치에서 정해지는 상수, SWIPE 9.5). 변 통과 기록은 `stroke-core`가 계산한다(숫자·기호·천지인 키용).

**한글 자음 키(이슈 #173, SRS FR-SWP-10~12):** 키 변 통과를 보지 않는다. 손을 뗄 때 **시작점 → 끝점 변위**(dp)만 쓴다. 이것은 **획 모양 판정**(탭 / 세로 획 / 가로 획 / 필순 반대)이고 모음을 정하지 않는다 — 모음은 `VowelStrokeAssembler`가 C 기준 위치·필순·후보로 정한다(4.3, 이슈 #212).

```
d = 끝점 − 시작점,  축 = |d.x| ≥ |d.y| ? 가로 : 세로,  길이 = 축 성분의 크기
if 길이 < 최소 통과 거리(minCrossDp)          → Tap(자음, 4.3)
else if 가로이고 d.x < 0  또는  세로이고 d.y < 0 → Reverse(반대 방향, 무시 + 오류 진동)
else                                           → 가로: 가로 획 / 세로: 세로 획
```
- **길이로 ㅣ·ㅡ / 점을 가르지 않는다**(오너 결정 2026-11-01, 이슈 #179: "이게 길이로 인식하는 것은 폐지해야 해."). 0.39의 `longDp` 분기(긴 획 / 점)는 없앴다. 획의 역할(ㅣ·ㅡ·가로 점·세로 점)은 `VowelStrokeAssembler`가 후보와 연결 위치로 정한다(4.3, SRS FR-SWP-19). 그래서 `StrokeResult`는 획 종류(세로 / 가로)와 함께 **시작점·끝점(dp, 화면 좌표)**을 넘긴다. `StrokeClassifier`는 길이(축 성분)를 탭/획 경계(`minCrossDp`)에만 쓴다. 두 획의 상대 크기 비교(ㅏ / ㅗ, ㅓ / ㅢ 특례)는 조립기가 시작점·끝점으로 한다(4.3).
- 중간 경로(구부러짐·되돌아옴)는 보지 않는다. 대각선 근처(45°)의 오판이 실기기에서 잦으면 LLD가 애매한 구간을 Reverse와 같은 무시로 정할 수 있다(SWIPE 3.1).
- 0.33까지의 한글 판정 순서(첫 나감 길이, 되돌아오기 길이, 꺾기 각도, 같은 변 통과 횟수, ㅣ 추가 길이)는 없앴다.
- 누르고 있기 판정은 없다(이슈 #142). 누른 시간은 결과를 바꾸지 않는다.

**숫자 키·기호 키(기호3·기호·기호2)·천지인 키:** 0.33과 같은 변 통과 판정(나감/들어옴, 최소 통과 거리 이상, 먼저 통과한 변). **입력기 테두리에 닿은 변**(`KeyGeom.outerEdges`, 창 테두리에서 `OUTER_TOLERANCE_DP` 0.5dp 안의 변)은 획이 테두리(± 같은 허용 오차)에 닿으면 그 방향 나감으로 센다 — 그 방향으로 누른 점에서 `minCrossDp` 이상 움직였을 때만, 변 너머 `minCrossDp`에 먼저 닿으면 그때(오너 지시 2026-11-02, 이슈 #237, SRS FR-SWP-45). 0.54까지는 바깥 변을 기록하지 않았다. 탭 자판(`TapGestureClassifier`)과 모드 키(`ModeKeyGesture`)도 같은 `EdgeCrossingTracker`를 쓰므로 같다.

| 키 종류 | 결과 해석 |
|---|---|
| 한글 자음 | 위 식: Tap / 세로 획 / 가로 획 / Reverse. 시작한 키의 자음은 넣지 않는다(이슈 #173) |
| 천지인 키(이슈 #160, 유지 확정) | 변 통과 없음 → ㆍ. 처음 통과한 변 위·아래 → ㅣ, 오른쪽 → ㅡ, 왼쪽(테두리, 이슈 #237) → 배정 없음 = ㆍ. 그 뒤 움직임은 보지 않는다(SWIPE 5.4, SRS FR-SWP-61) |
| 둘레 숫자 | 탭 숫자, ↑ 윗글자 기호, ←·→·↓ 배치표(SWIPE 7장. 이슈 #208로 2 ←·→ = `[ ]`, 6 ← 배정 없음, 4 ← = `;`(기호2 ←와 맞바꿈)), ↑ 문지르기 윗첨자, ↓ 문지르기 아래첨자. 나갔다 돌아옴·←·→ 문지르기 = 그 방향 나감(DCR-02) |
| 기호3·기호·기호2(이슈 #208) | 방향마다 한 기호(탭, ←, →, ↑, ↓) 배치표(SWIPE 8장, SRS FR-SWP-43): ↑ = 물리 키보드 짝(시프트), 기호 키 ←·→ = `( )`, 기호2 ← = `"`(숫자 4 ←와 맞바꿈, 이슈 #208). 단계 없음: 나갔다 돌아옴·문지르기 = 그 방향 나감. ↓ = 배정 기호, 없으면 탭(0.47까지의 ↓ = 탭 삭제). 기호3 ←·기호2 →는 테두리 쪽(이슈 #237), 배정 없음 → 탭 |

**ProgressState(안내용):** 지금 손을 떼면 나올 획 종류와, 그 획을 `SwipeInputMapper`의 조립 상태에 이었을 때의 결과(조립 모음 또는 ㆍ·‥, 지금 손가락 위치를 끝점으로 본 구역 판정)를 판정과 같은 코드로 계산한다. 한글 모음 획의 "길게 끌면 바뀌는 결과"는 세로 하나 뒤의 가로 획에서만 있다(앞 세로 획보다 길어지면 ㅏ → ㅗ, SWIPE 9.2). 누를 때는 조립 상태에서 이어 그을 수 있는 획과 결과 목록(획 안내, SWIPE 9.1)을 낸다. 앞 글자와의 조합 결과는 넣지 않는다(SRS FR-DSP-03, DCR-16).

### 4.3 SwipeInputMapper: 탭·획 → 자모 (gesture-engine)

이슈 #173(오너 결정·정정 2026-11-01)으로 **탭 = 자음(쌍자음은 쌍자음 키, 일반 자음 키와 같음), 모음 = 필순 획 조립**이다. 기준 키·쌍자음 후보·시간 비교는 없다(이슈 #168·#173). 받침·겹받침·도깨비불은 조합기(4.4)가 두벌식처럼 정한다(SWIPE 3·5장, SRS FR-SWP-10~21·30·34·36). 이름은 설명용이고 LLD가 정한다.

**상태:**
- **모음 획 조립기 `VowelStrokeAssembler`**: 지금까지 받아들인 획 열(획마다 획 모양(세로·가로)·시작점·끝점)과 **후보 모음 집합**(SWIPE 3.6.2 다음 후보 표, 정본 — 이 획 열을 필순의 앞부분으로 갖는 모음들). 새 획이 오면 지금 상태의 다음 후보 중 **이 획의 축에 맞는 후보만** 보고, 각 후보의 **연결 위치 구역**(SWIPE 3.6.3: 앞 획 경계 상자 기준의 쪽·높이, t = `posTolDp`)에 드는 하나로 정한다. 후보 밖 해석은 하지 않는다. 같은 상태·같은 축의 구역은 겹치지 않게 정의되어 있다(SWIPE 3.6.4). 어느 구역에도 들지 않으면 무시 + 진동(SRS TBD-21 확정). **dp 길이·닿음·거리 상한은 보지 않는다**(이슈 #179). 후보는 오토마타(올 수 있는 모음·겹모음)와 필순 규칙(왼→오, 위→아래 — 다음 획은 앞 획의 오른쪽·아래, SWIPE 3.6.2 필순 표)으로 예상한다. **(낱모음, C 없을 때) 세로 하나 뒤 가로 획은 두 획의 상대 크기로 ㅏ / ㅗ를 먼저 고른다**(가로가 짧으면 ㅏ, 길면 ㅗ, 같으면 입력 순서로 ㅏ, SRS TBD-23) — 그다음 그쪽의 최소 위치 조건(SWIPE 3.6.3)만 본다. 낱모음이면 첫 획 하나는 세로 = ㅣ(ㅗ·ㅛ 점 후보도 유지), 가로 = ㅡ(ㅓ·ㅕ 점 후보도 유지)로 보이고, 둘째 획이 앞 획의 역할을 다시 정하면 `ReplaceVowel`(기 → 고, 그 → 거). ㅓ / ㅢ(가로 하나 → 끝 자리의 세로 획, 끝 자리 = x ≥ R − t 또는 가로 획의 어느 부분이든 위에서 가로지름)는 둘 다 후보로 남기고, 보이는 모음은 높이 3등분(위·가운데 1/3 = ㅓ, 아래 1/3 = ㅢ)으로 정하되 **아래 1/3이어도 가로 획 길이 < ㅣ 길이 × 0.5면 ㅓ**(오너 결정, SRS TBD-22 확정, ㅓ / ㅢ 특례 — LLD는 상수 하나로 둠). ㅓ·ㅢ / ㅜ에는 상대 크기를 쓰지 않는다(둘째 획 시작 위치로 가름, 오너 확인). 동점 ㅏ·ㅗ의 점 가운데 높이·ㅕ ③·ㅝ ④ 가로지름은 설계 기본값(PM 승인). **자음 기준 C(SRS TBD-24 확정):** 조립기는 가운데 자음 자리 C(경계 상자)를 받아 **먼저 획의 역할을 정한다** — 역할은 **두 구역**으로 정한다(오너 결정·보충 2026-11-02, 이슈 #217): 가운데 점 P = (시작 + 끝)/2, d = (P.y − C.B) − (P.x − C.R). d > 0 = 아래 왼쪽(세로 = 세로 점, 가로 = ㅡ), d ≤ 0 = 오른쪽 위(세로 = ㅣ, 가로 = 가로 점). 버리는 획 없음. **첫 획은 두 역할 후보를 함께 들고**(구역 쪽을 보임) 둘째 획의 앞 획 기준 구역과 오토마타 후보로 확정한다. 둘째 획이 두 해석에 다 맞으면(ㅏ / ㅗ) 첫 획의 구역으로, 조립이 첫 획 하나로 닫히면 구역대로(점이면 버림). 둘째 이후 세로 획은 그 획의 구역으로 역할을 정한다. 0.52까지의 b·cy·cx·①~④·무시는 대체. 역할에 맞는 후보만 남긴 뒤 앞 획 기준 구역을 본다. C가 있으면 ㅏ / ㅗ 상대 크기, ㅜ / ㅓ·ㅢ·ㅠ / ㅟ의 x 경계, "아래" 구역(ㅜ ②·ㅠ ③)의 시작 높이 조건을 쓰지 않는다(낱모음에서만, 이슈 #192). 수치는 설계 기본값(SWIPE 3.6.3). 다음 획이 ㅔ로만 맞으면 ㅔ로 다시 정한다. 구역의 비율·배수는 LLD가 상수 한곳에 둔다. 지금 상태(모음 / 아직 모음 아님). 임시 상태는 셋(세로 획 둘 = ㅛ 앞, 가로 획 둘 = ㅕ 앞, ㅜ + 가로 점 = ㅝ 앞). 낱모음에서 ㅣ / ㅡ로 보이던 상태가 세로 둘·가로 둘(‥)이 되면 화면에는 ‥만 보인다(ㅣ / ㅡ를 지움, SWIPE 3.4, 이슈 #192). 조합기의 모음을 빼는 사건을 둘지, 조합기는 마지막 모음 상태(ㅣ / ㅡ)를 두고 표시만 바꿀지는 LLD — 닫을 때는 ㅣ / ㅡ로 되돌린다. `CheonjiinAssembler`와 같은 틀(요소 열 → 모음, 임시 상태, 무시, 요소 단위 ⌫)이고 요소와 표만 다르다. 두 조립기의 공통 부분을 `core-hangul`에 둘지는 LLD
- **천지인 조립기 `CheonjiinAssembler`**(core-hangul)

**accept(StrokeResult, key)** ── ACTION_UP에서. 시각은 보지 않는다(시간 판정 없음, 결정성).

| 들어온 동작 | 처리 | 내는 것 |
|---|---|---|
| 한글 자음 키 **탭**(쌍자음 키 포함) | 그 키의 자음 하나(쌍자음 키면 쌍자음). 조립 닫기. 같은 키를 두 번 탭하면 `Consonant` 둘 | `Consonant` |
| 한글 자음 키 **모음 획**(세로 획·가로 획, 시작 키 무관) | 천지인 조립 닫기. 획을 `VowelStrokeAssembler`에 넘김 | 조립기 결과: 모음이 처음 성립 → `Vowel`, 이어져 모음이 바뀜 → `ReplaceVowel`, 아직 모음 아님 → 없음(앱이 임시 ㆍ·‥ 표시), 이어질 수 없음 → 없음 + `Feedback` 오류 진동 |

| 천지인 키 탭·긋기 | 천지인 요소 하나. 모음 획 조립 닫기. 요소를 `CheonjiinAssembler`에 넘김 | 조립기 결과(위와 같은 방식) |

- **쌍자음 키 = 일반 자음 키와 같다(이슈 #168, #173 정정):** 위 표의 같은 행이고 내는 `Consonant`의 자음이 쌍자음일 뿐이다. 0.33의 두 번 탭 쌍자음(`UndoLast` + `DoubleConsonant`, 쌍자음 시간 창)은 쓰지 않는다.
- **누른 시간은 보지 않는다**(이슈 #142).
- **조립 닫기(SRS FR-SWP-15):** 모음 획이 아닌 입력(탭, 천지인 요소, 숫자·기호, 스페이스·엔터, 조합 확정 사건(모드 전환, 모드 키 ↑ 설정 열기 등))이 오면 `VowelStrokeAssembler`를 닫는다. 아직 모음이 아니면 마지막으로 모음이었던 상태로 되돌리고(그 뒤 획 버림) `Feedback` 오류 진동을 낸다(ㅜ + 가로 점 → ㅜ, 낱모음 세로 획 둘 → ㅣ, 낱모음 가로 획 둘 → ㅡ, SWIPE 3.3). 닫게 한 입력은 그대로 처리된다(탭이면 자음). 천지인 조립도 같은 방식으로 닫는다. 그래서 두 조립은 섞이지 않는다(SRS FR-SWP-62).
- **⌫(SRS FR-SWP-17, FR-CMN-07b):** 그래피티와 같이 먼저 조립기에 묻는다. 열린 조립기에 획이 있으면 마지막 획 하나를 빼고 남은 획으로 모음을 다시 계산해 조합기를 따라가게 한다(모음이면 `ReplaceVowel`, 모음이 아니게 되면 그 `Vowel`을 되돌리고 임시 표시). 조립기가 닫혔으면 조합기 입력 단위 목록에서 하나씩 뺀다: 단위는 `Vowel`·`ReplaceVowel` 이벤트 하나씩이고, 모음을 만들지 않은 점 획은 단위가 없다(곡 ⌫ = 고, ⌫ = ㄱ / 간 ⌫ = 가, ⌫ = 기, SWIPE 3.5). 닫힌 모음은 다시 열지 않는다(지운 뒤 새 획은 새 모음).
- **정리하는 때(SRS FR-CMN-03d):** 스페이스·엔터, 모드 전환·커서 이동·입력창 변경·입력 시작·끝 등 조합 확정 → 조립 닫기. 빈 칸·빈 띠 터치는 아무것도 바꾸지 않는다.
- **출력:** `JamoEvent`(Consonant, Vowel, ReplaceVowel). 긋기에서 `DoubleConsonant`·`UndoLast`·`MergeVowel`은 쓰지 않는다.

### 4.4 HangulComposer (core-hangul)

입력: `JamoEvent`. 출력: `ComposeResult(committed, composing)`. 생성할 때 **모드 정책**을 받는다.

| 정책 | 두벌식 | 긋기 | 그래피티 |
|---|---|---|---|
| 모음 병합 표 | 두벌식 표준(FR-HGL-04a) | 빈 표(복모음은 `VowelStrokeAssembler`가 만들어 `Vowel`·`ReplaceVowel`로 옴, 이슈 #173) | 쓰지 않음(천지인 조립 결과를 `ReplaceVowel`로 받음) |
| 백스페이스 | 마지막 입력 단위(키 하나) 되돌림 | 마지막 입력 단위(탭 하나, 쌍자음 하나, **모음 획 하나**(이슈 #173), 천지인 요소 하나) 되돌림(오너 결정 2026-10-30, 이슈 #150. 0.27까지는 조합 중 글자 통째로) | 마지막 입력 단위(자모 하나 또는 천지인 요소 하나) 되돌림 |

**입력 단위 목록:** 조합 중인 글자마다 그 글자를 만든 이벤트를 차례로 쌓는다. 백스페이스는 목록 끝에서 하나를 빼고 나머지로 상태를 다시 만든다(닭 ⌫⌫⌫ = 달, 다, ㄷ). 글자가 확정되면 그 글자의 목록은 버린다. 그래서 **백스페이스는 확정 경계를 넘지 않는다**(가가 ⌫ = 가ㄱ, 앞 가를 다시 열지 않음). `UndoLast`(긋기 쌍자음 바꾸기, 4.3)와 오류 복구(9장)도 같은 목록을 쓴다.

**다시 나누기 지원은 없앴다**(SRS FR-SWP-28 삭제, 이슈 #150). 긋기의 `UndoLast`는 조합 중 글자 안에서 끝나므로(4.3) 조합기가 확정된 글자를 보관하거나 확정 경계를 넘어 되돌릴 일이 없다.

```
상태: Empty → Cho → ChoJung → ChoJungJong(받침 1) → ChoJungJongJong(겹받침)
 · 모음 입력 시 받침이 있으면 받침(겹받침이면 뒤 자음)을 떼어 새 글자 초성(도깨비불)
 · 겹받침 자모 한 번에(SRS FR-HGL-02a, 이슈 #242): ChoJung이면 → ChoJungJongJong(갉), 그 밖이면 앞 글자를 끝내고 낱자 겹자음 하나(ㄺ). 낱자 + 모음 = 앞 자음 낱자 + 새 글자(ㄺ + ㅏ = ㄹ가). 받침에 붙은 겹받침은 입력 단위 목록에 두 자음(ㄹ, ㄱ)으로 쌓아 ⌫ = 둘째 자음만(갉 ⌫ = 갈, 두 번 치기와 같음), 낱자는 한 단위라 ⌫ 한 번에 통째로(PM 결정 2026-11-02, 이슈 #242, 원칙: 두 번 치기와 같은 결과)
 · 모음 연속(두벌식 키): 정책의 병합 표에 있으면 중성 교체, 없으면 새 글자. 긋기는 조립기가 복모음을 만들어 `ReplaceVowel`로 바꾸므로 병합 표를 쓰지 않는다(SRS FR-SWP-13·21)
 · ReplaceVowel(v): 조합 중 글자의 중성을 v로 바꿈(그래피티 천지인: ㅣ → ㅏ → ㅑ / 긋기 획: ㅗ → ㅚ → ㅘ)
 · UndoLast: 입력 단위 목록에서 마지막 하나를 되돌림(조합 중 글자 안에서만, 확정 경계를 넘지 않음)
 · Backspace: 정책대로(위 표). 조합 없음이면 앱이 확정 글자 한 글자 삭제. 누르고 있으면 반복(첫 지연 후 일정 간격, 반복 한 번 = Backspace 한 번, FR-CMN-07c)
```

app: ComposingController / HangulComposer(그래피티 정책)
   ▼
GraffitiPadView: 인식한 글자를 잠깐 표시(FR-GRF-07)

- **패드 상태 표시(SRS FR-GRF-05d, GRAFFITI 4.2, 이슈 #136):** `GraffitiPadView`는 획을 처리할 때마다(그리고 초기화 뒤) `GraffitiState`의 내부 언어·시프트·캡스록·구두점 시프트 대기·확장 시프트 대기를 읽어 다시 그린다. 문자 영역 왼쪽 위 구석 탭 영역에 점과 언어 글자("한"/"A"), 패드 구석 한 자리에 켜진 대기 표시(⇧·⇪·•·↘). 상태는 `GraffitiState`가 정본이고 뷰는 그리기만 한다. 인식 글자 표시(FR-GRF-07)와 달리 비밀번호 입력창에서도 그린다. 위치·크기·그림은 LLD-05 8.1.

- 그래피티 안의 한영 전환은 `GraffitiState`의 내부 언어만 바꾼다. 모드 키(FR-CMN-03)와 별개다(FR-GRF-05a).
- **ㆍ 중간 상태(FR-HGL-04e):** 첫 요소가 탭이라 모음이 성립하지 않은 동안(ㆍ, ‥)은 `CheonjiinAssembler`만 상태를 갖고 조합기에는 아무것도 넘기지 않는다. 앱은 조합 텍스트 뒤에 임시 글자(탭 한 번 ㆍ U+318D, 두 번 ‥ U+2025)를 붙여 `setComposingText`로 보인다. ㅣ·ㅡ로 모음이 성립하면 그때 `Vowel`을 넘긴다(도깨비불도 이때). 성립 전에 자음·스페이스·엔터·확정 획·모드 전환이 오거나 그 밖의 이유로 조합을 확정하면(숫자 영역 획, 영문·기호, 그래피티 안 한영 전환, 커서 이동, 입력창 변경) 조립기를 비우고 임시 글자를 버린다(DCR-21). 성립한 모음 뒤에 이어질 수 없는 요소(ㅐ + 탭, ㅣ + ㅣ, ㅡ + ㅡ 등)는 조립기가 무시한다. 상태·표시를 바꾸지 않고 요소 목록에도 넣지 않으며, `GraffitiPadView`의 인식 글자도 그리지 않는다(DCR-04, 오너 결정 #74 A). ‥ 다음 세 번째 탭은 시작하는 모음이 없으므로 무시한다(‥ 그대로). 조합 중인 글자가 없을 때의 탭도 같은 규칙으로 "ㆍ"만 표시하고, 모음이 성립하면 모음 단독 글자가 된다(ㆍ + ㅣ = ㅓ).
- **⌫ 순서(FR-CMN-07b):** ⌫는 먼저 조립기에 묻는다. 조립기에 요소가 있으면(ㆍ·‥ 임시 상태 포함) 조립기가 마지막 요소 하나를 빼고, 남은 요소로 모음을 다시 계산한다. 결과에 따라 조합기는 따라간다: 남은 요소가 모음이면 `ReplaceVowel`, 모음이 아니게 되면(거 → ㄱㆍ) 조합기의 그 `Vowel`을 되돌리고 임시 글자 표시로 바뀐다. 조립기에 요소가 없을 때만 조합기의 입력 단위 목록에서 뺀다. **조립기는 모음이 성립한 뒤 자음(받침)이 오면 닫혀 비워진다.** 닫힌 모음은 다시 열지 않으므로, 받침을 ⌫로 지운 뒤의 탭은 새 요소로 시작한다(각 ⌫ = 가, 이어서 탭 = 가ㆍ). 조립기의 요소 목록은 확정·닫힘 때 버린다. 그래서 가 ⌫ = 기(조립기 ㅣ), 이어서 탭 = 가 / 와 ⌫ = 외 / 각 + 탭 = 각ㆍ, ⌫ = 각 / 각 ⌫ = 가. 쌍자음(시프트 획 + 자음, 또는 붙여 쓴 한 획)은 자모 하나라 ⌫ 한 번에 지운다.
- **시프트 대기 중 ⌫:** 시프트·확장 시프트·구두점 시프트 대기 상태에서 ⌫를 누르면 대기만 취소하고 글자는 지우지 않는다(SRS 백스페이스 사례, DCR-05).
- **`GraffitiState` 시프트 규칙(SRS FR-GRF-05c, DCR-05):** 영문 캡스록 중 시프트 획 → 캡스록 끔(시프트 대기 없음). 한글 시프트 두 번 → 시프트 끔. 시프트가 쓰일 곳이 없는 획(쌍자음 없는 자음, 모음 요소, 숫자 영역 획) → 시프트 없이 해석하고 시프트 소멸. 대기 중 다른 제어 획 → 그 동작 + 대기 소멸. 대기를 만드는 획(시프트, 확장 시프트 사선, 구두점 시프트 탭)과 한영 전환 획도 제어 획이다 → 앞 대기를 지우고 자기 동작(새 대기, 전환). 판정 순서는 확장·구두점 대기의 기호표 획(직선·탭 모양 획도 기호표에 실리면 여기서 기호, 실리지 않으면 평소 뜻대로 아래 단계로, 확장 기호표에 탭은 없다, ⌫ 획(←)은 기호표에 싣지 않아 늘 대기 취소 — 오너 결정 #79 OD-3 A, GRAFFITI 4.2·6.2-8, 설계질의 #79. 기호표는 모양으로 찾고 길이로 가르지 않으며, 문자 영역 구석 탭은 기호표의 탭 `.`과 다른 획이라 한영 전환으로 간다 — GRAFFITI 6.4·6.5) → FR-GRF-05 조합(사선 + 탭 = 한영 전환, 영문 시프트 두 번 = 캡스록)·05c ①② → 그 밖의 제어 획(FR-GRF-05c ⑥, 설계질의 #6 Q2). 확장·구두점 대기 뒤 기호표에 없고 제어 획도 아닌 획 → 대기 소멸 + 평소대로 해석(05c ⑦, 오너 결정 #6 OD-2). 그래서 영문 대문자 = 캡스록 또는 시프트(둘이 함께 켜진 상태는 생기지 않는다).
- **한영 전환(DCR-06):** 그래피티 안의 한영 전환 획은 먼저 조합을 확정하고(임시 글자 버림) 내부 언어를 바꾼다. 모드 전환과 같은 처리다.
- **인식 실패(DCR-07):** 어느 획에도 맞지 않으면 입력 없이 `Feedback` 오류 진동만 낸다(SRS FR-GRF-08).
- **인식 글자 표시(FR-GRF-07):** 비밀번호 입력창에서만 그리지 않는다(FR-CMN-08 ①, DCR-19). 학습 금지 입력창에서는 그린다(FR-CMN-08 ②: 학습 금지는 학습·통계·기록만 끄고 표시는 끄지 않음, 오너 원칙 "학습 금지이지 암호처럼 출력 금지가 아니잖아!"). 그리는 것은 이번 획이 뜻하는 글자(자모·천지인 요소·영문 글자·숫자·기호, 시프트로 바뀐 글자)뿐이다. 글자가 없는 획(스페이스, ⌫, 리턴, 'J', 한영 전환, 대기 획), 인식 실패, 조립기가 무시한 천지인 요소(FR-HGL-04c)는 그리지 않는다(오너 결정 #74 A). 대기 상태 표시(GRAFFITI 4.2)는 이와 별개다(설계질의 #74).
- **초기화:** 모드 전환, 커서 이동, `onStartInputView`, 확정('J' 획 포함) 때 `CheonjiinAssembler`를 비우고 `GraffitiState`의 일회성 상태(시프트, 확장 시프트 대기, 구두점 시프트 대기)를 비운다. 캡스록과 내부 언어는 커서 이동·확정에서는 유지하고, 그래피티 모드에 새로 들어올 때 기본값(캡스록 끔, 한글)으로 돌린다.
- 숫자류 입력창(숫자·전화·날짜시간·비밀번호)에서는 그래피티가 아니라 영문 쿼티로 시작하므로(FR-CMN-04, 8.1) 숫자 입력창 전용 패드는 없다.
- **보조 줄:** 왼쪽부터 모드 키(72dp, 탭 자판 모드 키와 같음), 스페이스, ⌫, ↵. 모드 키 뒤 세 버튼은 남은 폭을 같게 나눈다(FR-GRF-01, DCR-12). 기능키는 누를 때 처리한다(FR-CMN-11a). 모드 키만 손을 뗄 때 탭(모드 전환) / ↑(설정 열기)를 가르고(8.2절), 모드 키에서 시작한 포인터는 패드 획으로 넘기지 않는다(위로 그어 패드에 들어가도 인식기에 주지 않음).
- 템플릿은 JSON(앱 리소스). 영문 글자·숫자·구두점·확장 기호 템플릿은 영문 단일 획 표(GRAFFITI 6.1·6.3·6.4, SRS FR-GRF-02, 오너 결정 #79 OD-1·OD-2 A)를 보고 그린다. 겹치는 모양의 처리는 GRAFFITI 6.5대로다(오너 결정 #79 OD-4~OD-7 A: 구두점 대기 + ↘ = `\`, 대기 뒤 어느 영역이든 기호표 모양이면 기호, 영문 K = 원본 α 고리, `•` 없음). 표의 미확인 획은 확정 전까지 T28 임시 템플릿을 유지한다. 개발용·평가용 획 샘플은 시험 데이터에 따로 둔다(NFR-09).
- **획 안내표 팁(SRS FR-GRF-09~09d, GRAFFITI 6.6, 이슈 #189):**
  - **데이터 = `recognizer.GuideCatalog`(JVM):** 언어와 상관없이 늘 같은 칸 목록 하나를 낸다(SRS FR-GRF-09b, 오너 보충 "영문과 한글 숫자를 한번에 표시해도 돼. 참고니까."). 구획 순서는 한글 → 영문 → 숫자 → 제어 획(공통 + 언어별 표시) → 기호(57, SRS TBD-26 확정)로 고정이다. 칸 = 정본 표의 한 행(①, 원본에 있으면 ②)이고, 그릴 모양은 **내장 `TemplateSet`의 템플릿 id**(점 열, 시작점이 첫 점) 또는 **규칙 획 종류**(↓ → ← ↑ ↙ ↘, 탭, 구석 탭, 두 번 긋기, 이어 쓰기)로 가리킨다. 한글 칸은 `KO_LETTER`, 영문 칸은 `EN_LETTER`, 숫자는 `NUMBER`, 기호는 `PUNCT`·`EXTENDED` 집합에서 찾으므로 같은 모양 다른 뜻(영문 K와 한글 ㅈ 등)도 각 구획의 칸으로 따로 나온다. 인식기와 같은 템플릿을 쓰므로 보이는 획과 인식하는 획이 어긋나지 않는다. 인식 여유용 템플릿 변형은 칸이 아니다. 임시(T28 interim) 템플릿을 가리키는 칸은 `interim` 표시를 갖고, 템플릿이 없어 인식되지 않는 획은 목록에 넣지 않는다(SRS TBD-11). 행 ↔ 템플릿 id 목록과 임시 표시를 런타임에 읽는 방법은 LLD-05에서 정한다. 시험: 모든 칸이 실제 템플릿이나 규칙 획으로 풀리는지, 구획 순서·구획별 칸 수, 임시 표시가 `TEMPLATES.md`의 interim과 같은지(JVM).
  - **그리기 = `GraffitiGuidePanel`(app, Canvas, 불투명 덮개):** 칸마다 획 선, 시작점 ●, 끝 방향 화살표, 뜻 글자를 그리고, 오른쪽 위 구석에 ✕를 그린다. 임시 칸은 점선 + "임시". 그림은 직접 그리고 비트맵은 쓰지 않는다(CON-6, FR-GRF-05d와 같은 원칙). 덮개 안 끌기는 세로 스크롤만 하고 입력·`GraffitiState`와 무관하다.
  - **소유·열기·닫기:** **빈 띠를 소비하는 `KeyboardRootView`**(창 높이 고정·바닥 정렬·빈 띠, LLD-08 7절)가 띠 오른쪽 끝의 안내표 버튼(1줄 × 1줄)과 덮개(`GraffitiGuidePanel`)를 가진다. `GraffitiPadView`는 5줄(패드 + 보조 줄) 그대로다. 버튼과 ✕는 키이므로 피드백을 누를 때 낸다(FR-CMN-11a ② 예외). 버튼은 누를 때 처리하고, ✕는 덮개 오른쪽 위에 고정(스크롤을 따라가지 않음)하고 손을 뗄 때 ✕ 안이면 닫는다. 누른 뒤 ✕ 밖으로 끌면 닫지도 스크롤하지도 않는다(FR-CMN-11a ① 예외, 세부는 LLD 몫). 이 소유에 맞춘 LLD-05·LLD-08 갱신은 개발 단계 몫이다. 열림 상태는 입력기 뷰가 가진 화면 상태일 뿐이고 `GraffitiState`·조합기·조립기에 아무것도 넘기지 않는다(그래서 조합 확정·초기화의 원인이 아니다). 닫는 때: 버튼, ✕, 그래피티 모드를 떠남(`ModeController`), `onFinishInputView`. 설정 변경(화면 회전 등)으로 `onCreateInputView`가 뷰를 다시 만들면 열림 상태를 되살리지 않고 닫힌 상태로 시작한다(세부는 LLD 몫). 덮개의 다른 곳 탭은 닫지 않는다(스크롤 끌기와 섞이지 않게).
  - **배치와 터치(오너 정정 #189, SRS TBD-25·FR-GRF-09a):** 덮개는 `GraffitiPadView`(패드 + 보조 줄, 5줄)와 같은 자리에 그 위로 겹쳐 놓는다. 빈 띠와 버튼은 덮지 않는다. **창 높이·인셋은 바뀌지 않는다**(5A 창 높이 규칙 그대로, 세로·가로 같음). 열린 동안 `KeyboardRootView`가 덮개 자리의 터치를 모두 덮개로 보내고 아래 `GraffitiPadView`(패드·보조 줄·모드 키)에는 보내지 않는다. 열 때 `GraffitiPadView`에 진행 중인 포인터가 있으면 결과 없이 버리게 한다(`ACTION_CANCEL`과 같은 처리: 획은 인식하지 않고 오류 진동도 없음, 보조 줄 키 반복은 멈춤, FR-CMN-11a ③). 조합·대기·언어 상태는 건드리지 않는다.
  - **입력창 종류:** 비밀번호·학습 금지 입력창에서도 그린다(`sink.restricted`를 보지 않음, FR-GRF-09d). 안내표는 아무것도 저장하지 않는다.

## 5A. 탭 자판 (TapKeyboardView)

- **배치(FR-TAP-03):** 편집 줄(Esc ⇥ ← ↑ ↓ → Del ⌫, 8 × 45) + 숫자 줄(10 × 36) + 글자 3줄(10 × 36 / 빈칸 18 + 9 × 36 + 빈칸 18 / 빈칸 18 + 7 × 36 + `-` 36 + ↵ 54) + 기능키 줄(한/영 72 · 스페이스 180 · `,` 36 · `.` 36 · `/` 36) = 6줄(이슈 #198: 기호 키 없음, ⌫는 편집 줄 오른쪽 끝, ↵는 아랫글자 줄, `-`는 m 오른쪽, `/`는 맨 아랫줄 오른쪽 끝). Esc·Del은 방향키처럼 조합을 확정한 뒤 `KEYCODE_ESCAPE`·`KEYCODE_FORWARD_DEL`을 보낸다(FR-TAP-13·14). Del은 ⌫·방향키와 같은 반복을 쓴다(잠정, TBD-27). 빈칸은 같은 줄의 가장 가까운 키로 친다(SRS 3.3). ⇧·캡스록·?123·가ABC 키 없음. 줄 높이는 설정값(기본 48dp, FR-SET-06).
- **기호 배정(FR-TAP-03a):** 키 데이터에 방향별 배정(탭, ↑, ←, →, ↓)을 둔다. `stroke-core`가 판정한 방향으로 배정을 찾고, 없으면 탭과 같게 처리한다. 숫자·기호를 넣기 전에 조합을 확정한다(FR-TAP-11a). **두벌식 겹받침 배정(SRS FR-TAP-02c, 이슈 #242):** 두벌식 자음 키(ㄱ·ㄴ·ㄹ·ㅂ·ㅅ·ㅌ·ㅍ)의 방향 배정에 겹받침 자모를 두고, 그 결과는 기호가 아니라 **자모 이벤트(겹받침 하나)**로 `HangulComposer`에 보낸다(조합을 확정하지 않음, 입력 단위 하나). 쿼티 배치 데이터에는 없다. 변 가운데 표시(FR-TAP-03b)는 같은 데이터에서 그린다 — 쿼티 ↑ 대문자, 두벌식 ↑ 시프트 자모도 키 데이터의 ↑ 결과에서 그린다(탭과 같은 글자·배정 없음·문지르기 결과는 그리지 않음, 이슈 #198).
- **배치는 데이터로 정의**한다(키 목록: 위치·크기·종류·글자·방향별 배정). 쿼티와 두벌식이 같은 뷰와 같은 형식을 쓴다. 따로 만든 숫자 키패드는 없다(숫자류 입력창은 쿼티, FR-CMN-04).
- **창 높이·바닥 정렬:** 키 영역 높이는 모드 중 가장 높은 자판(쿼티·두벌식 6줄)으로 고정한다. 긋기 자판도 6줄이라 창을 채운다(쌍자음 줄, 이슈 #168). 낮은 자판(그래피티 패드)은 바닥에 맞춰 그리고 위 띠는 비운다. 빈 띠는 터치를 소비하되 입력이 없다(그래피티 띠 오른쪽 끝의 획 안내표 버튼만 예외, 5장). 긋기 자판 맨 윗줄(숫자 1~7) 키의 ↑ 나감은 창 밖으로 나가도 이동 이벤트를 계속 받아 보통 변 통과로 센다(10장 R2). 모드 키는 모든 모드에서 맨 아랫줄 왼쪽이라 화면 위치가 같다.
- **시스템 막대 여백(SRS FR-TAP-03 아래 창 규칙, 오너 결정 #93 OD-1·2·3 A):** 입력 뷰는 창 인셋 중 내비게이션 바(`navigationBars`)와 시스템 버튼 줄(`tappableElement`)을 **변마다 큰 값**으로 받아 안쪽 여백으로 둔다. 키 영역(6줄 고정 높이, 낮은 자판은 그 안에서 바닥 정렬)은 여백 안쪽에 그리고, 여백은 키보드 배경색으로 칠한다. 아래 변은 늘, 옆 변은 가로 화면 3버튼 내비게이션처럼 막대가 옆에 올 때 같은 방식으로 비운다. 여백은 빈 띠와 같이 터치를 소비하되 입력이 없다. 창 높이 = 6줄 + 아래 여백.
- **자판 폭과 정렬(SRS FR-CMN-14·FR-SET-09, 오너 결정 2026-11-02, FSS#25):**
  - **계산은 순수 함수 하나**(`KeyboardWidth`, 안드로이드 없음, 단위 시험): 입력 = 가용 폭 A(dp, 입력 뷰 폭 − 옆 시스템 막대 여백), 화면 짧은 변 A_v(dp, 세로 화면의 가용 폭), 그 화면 방향의 설정값(폭 비율 p 또는 "세로와 같은 크기", 정렬) → 출력 = 자판 폭 W와 가용 폭 안의 왼쪽 위치 x. W = min(A, max(320, A × p)), "세로와 같은 크기"면 p 자리에 A_v / A. x = 0(왼손모드), (A − W) / 2(중앙모드), A − W(오른손모드). 화면 방향은 입력 뷰가 놓인 구성(세로·가로)이고, 설정값은 방향마다 따로다(7.3).
  - **놓기:** 입력 뷰 루트(`KeyboardRootView`)가 잴 때 W를 구해 모드 뷰·그래피티 안내표 덮개를 폭 W로 재고, 놓을 때 옆 여백 + x에 둔다. 안내표 버튼은 자판 오른쪽 끝(x + W − 버튼 폭)의 빈 띠에 둔다. 높이·바닥 정렬은 그대로다. 남는 자리는 루트 배경(키보드 배경색)이고 루트가 터치를 소비한다(빈 띠·시스템 막대 여백과 같은 길, 입력·피드백 없음). 안드로이드는 다른 손가락이 자식을 누르고 있으면 자식 밖에 닿은 새 손가락(`ACTION_POINTER_DOWN`)도 그 자식에 붙여 보내므로, 루트는 **자식 밖에서 시작한 포인터를 자식에 넘기지 않는다**(그 포인터의 내려옴을 보내지 않으면 나뉜 이동·올라옴도 자식에 가지 않음, LLD). 그래피티 위 빈 띠도 같다.
  - **배치·판정 코드는 바꾸지 않는다:** 모드 뷰(`TapKeyboardView`·`SwipeKeyboardView`·`GraffitiPadView`)는 이미 받은 폭으로 기하(키 사각형, 위치 허용 오차 = 실제 키 폭 × 0.4, 가운데 글자 자리 C, 패드 구역)를 만든다. 그래서 키 폭은 W에 비례해 줄고 C의 가로 중심은 줄인 자판의 가운데다(SWIPE 9.5). 입력기 테두리 판정(FR-SWP-45)은 모드 뷰 좌표의 왼쪽 0·오른쪽 폭을 테두리로 보므로 줄인 자판의 바깥 변이 곧 테두리다. 손가락이 여백으로 나가도 DOWN을 받은 모드 뷰가 이동을 계속 받는다(안드로이드 터치 대상 유지, 10장 R2와 같은 성질).
  - **다시 놓기:** 화면 방향이 바뀌면(`onConfigurationChanged`, 8장) 그 방향의 값으로, 설정 흐름(Flow)에서 폭·정렬이 바뀌면 곧 루트가 다시 잰다(줄 높이 설정과 같은 길). 모드·조합 상태는 건드리지 않는다.
  - **입력 연습:** 연습 화면(`PracticeActivity`, 7.1)의 자판 틀도 같은 함수로 폭·자리를 정한다. 가용 폭 = 그 화면의 자판 자리 폭, 방향 = 연습 화면의 구성. 남는 자리는 자판 틀 밖의 키보드 배경색 여백이고 터치를 소비한다.
- **글자 키 획:** `stroke-core`로 ↑·↓·문지르기를 판정해 탭 자판 동작 표(SRS 3.3)대로 입력한다. 나갔다 돌아옴과 ←·→ 문지르기는 그 방향 나감으로 본다(DCR-02). 시프트 상태는 없다(↑ 나감이 유일한 시프트).
- **처리 시점(SRS FR-CMN-11a, DCR-11):** 기능키는 누를 때, 키 입력 진동·소리도 누를 때. 모드 키만 뗄 때 결과를 정한다(8.2절, 이슈 #205). `ACTION_CANCEL`이면 아직 떼지 않은 모든 포인터가 결과 없이 대기열에서 빠지고 반복은 멈춘다. 이미 뗀 포인터의 대기 결과는 누른 순서대로 낸다.
- **여러 손가락(FR-CMN-11):** 포인터마다 따로 추적한다. 글자·숫자·기호 키는 결과를 각 포인터를 뗄 때 정하고, 출력은 누른 순서로 낸다. 먼저 누른 글자·숫자·기호 키가 아직 눌려 있으면 뒤 포인터의 결과를 대기열에 두었다가 앞 결과가 나온 뒤에 낸다. 기능키(⌫, 스페이스, ↵, ⇥, 방향키)는 누르는 즉시 처리하고 대기열에 들어가지 않으며, 다른 키를 기다리게 하지도 않는다. 모드 키는 뗄 때 결과를 정하므로 글자·숫자·기호 키처럼 대기열 순서에 든다(SRS FR-CMN-11, 이슈 #205).
- **탭 키:** 조합 확정 → `commitText("\t")`.
- **방향키:** 조합 확정(`finishComposingText`) → `sendKeyEvent(KEYCODE_DPAD_LEFT/RIGHT/UP/DOWN)`. 누르고 있으면 반복(첫 지연 후 일정 간격).
- **⌫:** 누르고 있으면 반복(방향키와 같은 타이머, FR-CMN-07c).
- **접근성(NFR-07):** 커스텀 Canvas 뷰에 `ExploreByTouchHelper`로 키마다 가상 접근성 노드를 제공한다(쿼티·두벌식).
- 한자 변환은 범위에서 뺐다(SRS 1.2절).

## 7. 입력 연습과 저장소

### 7.1 입력 연습 (옛 튜터 모드, FSS#17)

오너 방향(2026-11-02, FSS#17)에 따라 영문 대문자·기호·그래피티·긋기 입력을 **주제별로 골라서 짧게** 연습한다. 아무것도 재지 않는다(기준값 고정, SRS 1.3). 규칙의 정본은 SWIPE 10장이다(10.0 화면, 10.1 주제·항목, 10.2 판정). 코드 이름은 `PracticeActivity`·`PracticeItemJudge`로 바꾼다(옛 `TutorActivity`·`TutorItemJudge`). 요구사항 ID(SRS FR-TUT)는 그대로 둔다.

```
PracticeActivity(옛 TutorActivity)
  └─ 주제 목록 = ①②③④ (SWIPE 10.1)
       │     주제마다 이름·한 줄 설명·어림 시간·해 본 표시(✓, SettingsStore의 값, 판정에 안 씀)
       │     그 모드가 키보드에서 꺼져 있으면 ③·④에 "꺼져 있음" 표시(할 수는 있음, SRS FR-CMN-03f ⑦)
       ├─ 주제 설명(한 화면) → [시작]
       ├─ 항목을 정해진 순서로 한 번씩(되풀이·표본 없음). 다 맞히면 끝 화면 → 주제 목록. [그만]은 언제든 주제 목록으로
       ├─ 연습 자판 = 주제·항목이 정함(실제 키보드와 같은 뷰·엔진·고정 기준값):
       │     ①·② 탭 자판: 실제 탭 자판 그대로(TapKeyboardView 배치 데이터(영문 쿼티), 편집 줄·⌫ 포함) + stroke-core 탭 자판 동작 표(↑ 대문자·짝 기호, ←·→·↓ 배정)
       │     ②의 긋기 항목·④ 긋기 자판: SwipeKeyboardView + StrokeClassifier·SwipeInputMapper(4.2·4.3), GuideOverlay·ProgressState(6장)를 같은 타이머로, 획 자국·가운데 자음 포함(SRS FR-TUT-11)
       │     ③ 그래피티: GraffitiPadView + recognizer(5장) + GraffitiGuidePanel을 늘 펼친 상태로. 항목마다 패드의 한영 상태를 목표에 맞춤
       ├─ 입력 표시: 마지막 한 글자 크게(SRS FR-TUT-09, 임시 ㆍ·‥ 그대로). 조합기는 실제와 같은 HangulComposer(4.4)
       ├─ PracticeItemJudge(옛 TutorItemJudge): 동작(터치 하나, 그래피티는 획 하나)마다 실제 판정 결과를 목표의 같은 차례와 비교 → 다르면 ✗, 다 맞으면 ✓(SRS FR-TUT-12)
       │     ✗ → 쓰는 법 안내(SWIPE 10.2절 문구 규칙: 탭 자판 = 키와 방향, 그래피티 = 안내표 칸 강조, 긋기 = 획 차례와 자리), 같은 항목 다시
       │     항목 시작·다시 할 때 연습 자판·조합 상태를 비움(탭 자판 항목은 ✗ 뒤 비우지 않고 ⌫로 이어 씀)
       └─ 재는 것·저장하는 것 없음
첫 실행: SettingsActivity가 처음 한 번 주제 목록만 연다(연습은 시작하지 않음, SRS FR-TUT-01). 그 뒤는 설정의 "입력 연습"으로만
```

- **판정 입력:** `PracticeItemJudge`는 Android 의존 없는 순수 Kotlin으로 `app` 소스에 두고 JVM으로 시험한다. 입력인 동작 기록은 공통 타입이다(넣은 글자 또는 자모·천지인 요소, 무시·인식 실패 표시). 탭 자판 항목은 ⌫를 반영한 글자열로 판정한다(앞부분이 아니면 ✗, 항목을 비우지 않고 ⌫로 고쳐 이어 씀, 같아지면 ✓, SWIPE 10.2). 이름·타입 세부, ✓·✗ 표시 시간, 화면 문구는 LLD.
- **빠지는 것(FSS#17):**
  - 1·3·5과 차례와 과 번호, 단계 목록(1-1·1-2·3-1·3-4·5-1) — 주제·항목 목록으로 바뀐다.
  - 번갈아 쓰기·되풀이·표본 수·짝 규칙, 위치 오차 기록(`calibration.position`).
  - 1-1·1-2 특별 판정과 "✓이면 목표 글자로 바꿈"(SRS TBD-17 해당 없음).
  - 5과 문장·`TypingStats`·5과 ⌫, 19자음 돌림(오너 결정 ③).
  - 기준값 저장 파일과 내보내기·가져오기·초기화 메뉴(오너 결정 ①, 7.2·7.3).
  - 그 전의 `ThresholdEstimator`·흔들림 여유·겹침 다시 하기, 시간 창 계수, 3-2·한 획 복모음 측정은 이미 없앴다.
- 최소 통과 거리는 **dp 절댓값**이다. 가로 화면이나 줄 높이 설정(FR-SET-06)·자판 폭 설정(FR-SET-09)으로 키 크기가 달라져도 비율로 바꾸지 않는다(SRS FR-CMN-12). 위치 허용 오차만 **실행 때의 실제 키 폭** × 0.4로 셈한다(그때 그려진 긋기 자판 키의 폭, PM 결정 2026-11-02, FSS#17). 키 폭이 바뀌면 함께 바뀐다.
- `minCrossDp` 하나를 긋기 자판과 탭 자판·모드 키·그래피티 보조 줄 모드 키가 함께 쓴다. 긋기 자판에서는 한글 탭/획 경계(누른 점 → 뗀 점 변위)와 숫자·기호·천지인 키·모드 키의 변 통과 인정(키 변 너머 거리)에 쓴다. **값은 8dp 고정**이다(오너 결정 2026-11-02, SRS TBD-29 확정). 0.50까지의 기본값은 14dp였다.
  - **영향(설계자 확인):** 숫자·기호·천지인 키와 탭 자판 ↑·↓의 나감·들어옴도 변 너머 8dp다(`EdgeCrossingTracker`가 같은 값을 받음). 이 문턱은 누른 점이 아니라 **키 변에서** 잰다. 그래서 키 가운데를 누른 탭은 반 키(약 25dp) + 8dp를 움직여야 나감이 되고, 안드로이드 touch slop(누른 점에서 8dp)보다 둔하다. 나갔다 돌아옴(같은 변 2번)·문지르기(3번 이상)는 변 안팎을 8dp씩 오가야 해 흔들림으로 생기기 어렵다.

### 7.2 기준값

입력 연습은 아무것도 재지 않으므로 기준값은 모두 **고정값이고 코드 상수**(`ThresholdDefaults`)로 둔다(오너 결정 2026-11-02, FSS#17 ①). 기준값 저장 파일과 설정의 내보내기·가져오기·초기화 메뉴는 없다. 옛 저장 파일(형식 1~6)은 읽지 않는다. 남은 파일을 지울지는 LLD가 정한다.

| 기준값(SRS 1.3) | 값 | 단위 |
|---|---|---|
| 최소 통과 거리(`minCrossDp`) | **8** | dp |
| 표시 지연(`guideDelayMs`) | 120 | ms |
| 위치 허용 오차(`posTolDp`) | 실행 때의 실제 키 폭 × 0.4 | dp |

0.60까지의 "튜터 단계 ↔ 기준값 ↔ 저장 칸" 표, JSON 예시, 저장 형식 1~6의 설명은 변경 이력에 남긴다.

### 8.1 ModeController: 모드 키 규칙

```
상태: current, previous(없을 수 있음), typed
순서: SWIPE → QWERTY → DUBEOLSIK → GRAFFITI → SWIPE … (설정에서 꺼진 모드는 건너뜀, FR-CMN-03f)
켜진 모드: enabled ⊇ {QWERTY, DUBEOLSIK}(늘 켜짐), GRAFFITI·SWIPE는 SettingsStore 값(기본 켬, FR-SET-08)
nextEnabled(m) = 순서상 m 다음의 첫 켜진 모드

입력 이벤트(글자·숫자·기호, 그래피티 천지인 요소 획, 스페이스, 엔터, 탭, 지우기) → typed = true
  (방향키, 모드 키, 그래피티 한영 전환·시프트·캡스록·확장 시프트·'J' 확정 획 → 입력 아님, DCR-17)
입력창 바뀜(onStartInputView) → typed = false, previous 유지          // FR-CMN-03e
  숫자류 입력창이면 enterNumericField():                                 // FR-CMN-04, 04b
    if returnMode == null: returnMode = current
    current = QWERTY                       (previous·마지막 모드 저장 안 바꿈)
  아니면 leaveNumericField():
    if returnMode != null: current = returnMode; returnMode = null   (previous 안 바꿈)
applyEnabled(enabled)  — 설정이 바뀌었을 때(키보드가 떠 있으면 곧바로)와 onStartInputView마다    // FR-CMN-03f ②~④
  if previous ∉ enabled: previous = null
  if returnMode != null and returnMode ∉ enabled: returnMode = nextEnabled(returnMode); 마지막 모드 저장(= returnMode)
  if current ∉ enabled: 확정·조립기 초기화(FR-CMN-03d); current = nextEnabled(current)   (typed·previous 안 바꿈)
                        if returnMode == null: 마지막 모드 저장
프로세스 시작 → current = 저장된 마지막 모드(꺼져 있으면 nextEnabled로 고치고 마지막 모드로 저장), previous = 없음, typed = false, returnMode = 없음
모드 키 →
  확정(finishComposingText, 입력 단위 목록은 확정으로 소멸), SwipeInputMapper의 모음 획 조립기·천지인 조립기 초기화   // FR-CMN-03d
  if typed and previous != null and previous != current:  next = previous      (previous는 늘 켜진 모드, applyEnabled)
  else:                                                    next = nextEnabled(current)
  if typed: previous = current
  current = next; typed = false
  if returnMode == null: 마지막 모드 저장(DataStore)   // 숫자류 입력창 안에서 바꾼 모드는 저장 안 함, FR-CMN-04b
```

- 순수 Kotlin 상태 기계로 만들어 SRS 모드 키 예시 표 10행, 숫자류 입력창 사례 표 7행, 꺼진 모드 사례 표 8행(FR-CMN-03f)을 단위 시험한다. 켜진 모드 집합은 밖(`SettingsStore`)에서 받아 넣는다.
- **설정 변경 전달:** `KeyboardService`가 `SettingsStore`의 켜진 모드 값(Flow)을 구독한다. 값이 바뀌면 `applyEnabled`를 부르고, 입력 뷰가 떠 있는 동안 `current`가 바뀌었으면 입력 뷰를 새 모드의 뷰로 바꾼다(`setInputView`, 모드 전환과 같은 경로). 떠 있지 않으면 다음 `onStartInputView`의 `applyEnabled`가 맡는다.
- 그래피티 안의 한영 상태(`GraffitiState`, 5장)는 `ModeController`와 따로이고 켜진 모드와 상관없다(FR-CMN-03f ⑥).
- 숫자류 입력창 안에서도 모드 키는 위 규칙 그대로다(typed·previous 포함). 마지막 모드 저장만 하지 않으므로, 숫자류 입력창 안에서 프로세스가 다시 시작되면 저장된 마지막 모드(= 돌아갈 모드)를 `returnMode`로 삼아 다시 쿼티로 시작한다(사례 표 7행).
- 위 "모드 키 →"는 모드 키의 **탭** 결과(8.2절의 `ModeKeyTap`)일 때만이다. ↑(설정 열기)는 `ModeController`를 거치지 않는다.

### 8.2 모드 키 획: 탭 = 모드 전환, ↑ = 설정 (SRS FR-CMN-13, 오너 결정 2026-11-02, 이슈 #205)

- **공용 판정 `ModeKeyGesture`:** 세 입력 뷰(탭 자판, 긋기 자판, 그래피티 보조 줄)의 모드 키가 같은 판정을 쓴다. 누를 때 키 입력 진동·소리만 내고(FR-CMN-11a ②), 포인터를 따라가며 `stroke-core`의 변 통과 기록(최소 통과 거리, 화면 끝 바깥 변은 기록하지 않음 — SRS FR-SWP-03·45)에서 **처음 통과한 변**을 본다. 손을 뗄 때 첫 변이 위면 `OpenSettings`, 아니면(통과 없음, ←, →) `ModeKeyTap`이다. 되돌아옴·문지르기·꺾기·길이는 보지 않는다(천지인 키 결과(4.2)와 같은 "첫 변" 해석). `ACTION_CANCEL`이면 결과가 없다(SRS FR-CMN-11a ③).
- **`ModeKeyTap`** → 8.1 모드 키 규칙 그대로.
- **`OpenSettings`** → 조합 확정(`finishComposingText`, 방향키·Esc와 같음) → `SwipeInputMapper`의 모음 획 조립기·천지인 조립기 닫기(FR-CMN-03d와 같은 정리. 획 자국·가운데 자음도 지움, SRS FR-DSP-09·10) → 설정 화면(`SettingsActivity`) 시작. `ModeController`의 current·previous·typed·returnMode와 마지막 모드 저장은 바꾸지 않는다(SRS FR-CMN-03a: 모드 키는 입력 아님). 입력기 서비스에서 액티비티를 여는 방법(플래그 등)은 LLD에서 정한다.
- **처음 누른 키로만 판정:** 손가락이 위 줄 키·빈칸·긋기 자판 빈 칸·그래피티 패드로 넘어가도 그쪽은 입력이 없다. 긋기 자판에서는 모드 키에서 시작한 포인터를 `StrokeClassifier`의 모음 획으로 보내지 않고, 그래피티에서는 인식기(`InkCollector`)에 넣지 않는다.
- **여러 손가락:** 탭 자판은 글자 키와 같은 대기열 순서(SRS FR-CMN-11). 긋기 자판·그래피티 패드는 한 획 진행 중 다른 손가락을 무시하는 지금 규칙 그대로다.
- **그래피티 획 안내표 덮개**가 열린 동안은 모드 키가 덮개 아래라 터치가 닿지 않는다(5장, SRS FR-GRF-09a).
- **단위 시험(JVM):** 변 통과 기록 → 결과: 탭(이동 없음·최소 통과 거리 미만), ↑, ←, →, ↑ 뒤 되돌아옴(= ↑), → 뒤 위로 꺾음(= 탭), 테두리 변(←·↓)에 닿음(= 그 방향 나감, 모드 키는 탭과 같음, 이슈 #237). `OpenSettings` 뒤 `ModeController` 상태 불변.

## 9. 오류 처리

- 엔진 호출(`update`, `finish`, `accept`, `recognize`, 조합기 이벤트)을 획 단위로 감싼다. 예외가 나면 그 획은 결과 없이 버리고, 조합 상태는 획 시작 전으로 되돌린다(입력 단위 목록 이용, 4.4). 긋기는 `SwipeInputMapper` 상태(조립기)도 획 시작 전으로 되돌린다. 오류는 7.3의 규칙대로 기록한다(NFR-03, NFR-05).
- 기준값 파일이 없거나 손상되면 기본값으로 동작한다(FR-TUT-05). 따로 안내하지 않는다.
- `InputConnection`이 없으면(null) 아무것도 쓰지 않는다.

## 11. 시험 설계

| 수준 | 대상 | 방법 |
|---|---|---|
| 단위(JVM) | `core-hangul` | 자모 입력열 → 기대 문자열 표: 받침, 겹받침, 도깨비불, **방식별 병합(두벌식 ㅇㅗㅐ = 왜, ㄱㅏㅣ = 가ㅣ / 긋기 가 + ㅣ = 가ㅣ, 고 + ㅏ = 고ㅏ)**, `ReplaceVowel`, 백스페이스 사례 표(SRS 3.1, 연속 ⌫·확정 경계 포함, 긋기 자모 단위). `CheonjiinAssembler`(이슈 #160로 recognizer에서 옮김, 그래피티 시험 사례 그대로) |
| 단위(JVM) | `stroke-core` | 궤적 + 키 사각형 → 변 통과 기록, 테두리 변 닿음 = 나감(누른 점에서 minCross 미만이면 아님, 이슈 #237), 탭 자판 동작 표 |
